# 单实例部署

从coding目录运行：

```sh
docker compose -f deploy/compose.yml up --build -d
```

入口为 `http://127.0.0.1:8080`。Nginx负责网页和同域 `/api` 反代，后端端口不映射到宿主机；数据在命名卷 `episode-data` 内。默认绑定本机，避免开发配置直接暴露公网。

对外部署时在入口前配置受管理的HTTPS反向代理并设置实际允许的 `EPISODE_CORS_ORIGINS`；原生移动端也使用该HTTPS API地址。不要把数据卷挂成静态目录，不要将备份放在公开网站目录。服务默认开放工作室自注册；若仅供内部试点使用，应通过入口访问控制限制注册入口和访问范围。

SQLite适合本次单实例服务工作台。此配置固定一个backend进程；未做多机高可用或大并发容量承诺。转为多副本前应迁移为共享数据库和私有对象存储，并重测并发、下载授权及恢复。

## 文件与质检

应用限制上传大小并核验媒体信息/SRT结构，Nginx限制总请求101MB。正式上线需在运行环境设置资源隔离、磁盘配额和定期备份；不因上传成功自动认定文件业务质量合格。公网上线前按实际素材规格和客户并发完成容量测试。

## 备份恢复

按backend/README.md使用备份命令。备份必须覆盖数据库和文件；仅备份SQLite会丢失实际成品。恢复先在新的空目录演练，验证登录、订单历史和带权限的成品下载。不要覆盖运行中数据库，不要依赖容器临时层保存客户资料。

## 当前验证范围

应用本机验证结果见 `../docs/verification.md`。Docker配置是可重复部署材料；只有实际Docker构建/启动记录才表示该环境通过。域名、TLS证书、生产主机与商店分发均需部署环境提供，本次不自动购买或对外发布。
