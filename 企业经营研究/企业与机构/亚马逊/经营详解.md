# 亚马逊：经营详解

补充日期：2026-09-26。与[原研究](README.md)配合阅读；本页聚焦经营账、机制操作与边界，[案例](案例.md)检验这些解释。

## 1. 先区分三种客户关系

零售消费者购买的是选择、价格、交付确定性和售后；卖家购买的是接触消费者以及处理订单的能力；AWS 客户购买的是可调用的技术资源。三者都可能重视便利，但付费依据、合同周期和风险完全不同。平台不能用一个“客户满意”总分代替三种关系的质量。**研究推断：**消费者少付钱、卖家多赚钱、平台提高利润并非时时同时成立，经营机制需要显式处理冲突。

例如，卖家为了获得订单可能提高广告支出；这能增加平台收入，却不能单独证明消费者找商品更容易。物流服务可以省去卖家自建仓库的固定投入，也可能使其更依赖一个渠道。研究应把“交易发生了”与“交易双方获得净收益”分开，把平台提供的技术服务与其分配流量的权力分开。

## 2. 经营账与数据口径

以下金额为**2025 自然年、亿美元**。来源为 [2025 SEC Form 10-K](https://www.sec.gov/Archives/edgar/data/1018724/000101872426000004/amzn-20251231.htm)，核对了合并损益、分部与服务分类表；比例为研究者据披露数计算。

| 指标 | 数值 | 能说明什么／不能说明什么 |
|---|---:|---|
| 集团净销售额 | 7,169.24 | 包含商品销售与服务费；不是全平台成交总额 |
| 经营利润 | 799.75 | 经营利润率约11.2%；不能当现金回报率 |
| AWS收入／经营利润 | 1,287.25／456.06 | AWS约占集团经营利润57%；不代表其占现金流同样比例 |
| 第三方卖家服务收入 | 1,721.62 | 包含佣金、履约配送等费用；不是全部卖家销售额 |
| 广告／订阅收入 | 686.35／496.19 | 订阅包括Prime以外的服务；两者均没有独立完整利润表 |
| 销售成本／履约费用 | 3,564.14／1,090.74 | 分类不同，不能把履约费用简单视为全部物流成本 |

**研究推断：**平台化会改变每一美元收入所代表的经济活动。若订单从自营变成第三方，商品可能仍由同一消费者买走，但平台收入只确认其相应服务费。因此比较零售商收入、毛利率和增长时，要先对齐总额法与净额法、物流承担方式及广告收入，不能把表面高毛利自动解释为生产效率高。

同样，AWS经营利润需要与资本投入、折旧、设备更新和长期容量承诺一起观察。利润上升而资本开支更快增加时，现金回收可能变慢；客户预付、应付账款和库存周转则可能暂时改善现金流。更好的分析单位是业务生命周期，而非只看单一季度的利润。

## 3. 客户倒推如何进入实际决策

官网转载的前员工著作节选介绍了 PR/FAQ：先描述客户将获得的体验，再通过问答暴露难点，反复修改后决定是否立项。这是公开的过程说明，不是证明成功率的实验。[PR/FAQ流程说明](https://www.aboutamazon.com/news/workplace/an-insider-look-at-amazons-culture-and-processes)

**研究建议，非公司规定：**实际借鉴可准备一页客户承诺与一张证据表。证据表分别写“客户当前付出的代价”“新方案减少哪一种代价”“愿付价格”“最容易失败的假设”“验证预算”。让产品、工程、运营和财务各指出一个致命约束，避免所有人只润色同一篇新闻稿。立项后，将承诺翻译成可监测结果，如交付失约率、退货原因和客户完成任务的时间，而不是只数功能。

这套方法更适合价值主张尚不清晰的项目。已经明确的安全漏洞修补不应为写营销式文档而延误；基础研究也未必一开始就能准确预测最终客户场景。管理者要判断哪些未知必须先验证，哪些未知可以在有限预算内探索。

## 4. 决策速度、组织责任与激励

2016年股东信强调对可逆决策采取较轻流程、信息不完备时行动以及及时纠偏；这些是管理层的决策主张。[2016股东信](https://www.aboutamazon.com/news/company-news/2016-letter-to-shareholders)

**研究推断：**“可逆”至少包含技术、经济与社会三个维度。界面按钮可以回滚，但用户已被错误收费、个人信息已泄漏或商家已退出，损失未必可逆。授权前应列明损失上限、恢复时间、被影响人群以及谁可以叫停。速度不是省略责任，而是让审批强度与后果相匹配。

文化原则可以成为招聘和评估的共同语言，但激励仍要看实际奖励什么。若负责人因转化率受奖，却不用承担退款、投诉与监管成本，客户导向会被局部优化替代。研究者应追问：负责增长的人是否看到取消、退款和误订数据？异常能否升级到独立于业绩目标的审查者？组织是否奖励主动停止一个看起来增长很快但损害客户的方案？公开材料不足以证明这些安排在所有业务一致执行。

## 5. 资本配置：基础设施、选项与止损

**研究推断：**亚马逊式扩张可以拆成三类资本。第一类用于已有需求的可靠交付，如仓储和服务容量；第二类用于把内部能力变成外部产品，需要新增售前、计费、服务等级与支持能力；第三类是对新客户行为下注，如新设备和新零售体验。三类投资不能使用同一考核期限，也不能都以“战略重要”免除回报责任。

一个可迁移的投前表应写明：基准需求、悲观需求、复用资产、不可回收资产、阶段性证据、继续投资与关闭权限。若项目失败仍能留下软件、团队或供应链经验，应提前定义其接收方；失败后宣称“我们学到了很多”，不等于证实这些资产产生了后续收益。Fire Phone案例正适合检验这一点。

## 6. 风险、替代解释与使用边界

履约速度改善可能同时来自区域布局、预测改进、商品组合和利用率变化；利润改善也可能受到价格、广告占比、会计估计和需求影响。不能把同年发生的管理改革与财务改善自动连成因果链。比较时应尽可能采用相似订单、相似距离和相同服务承诺，并检查成本是否转移给卖家或员工。

平台扩张还有治理成本。FTC关于Prime注册与取消的案件已进入和解与执行阶段，不能和另一宗平台反垄断诉讼混称为同一种裁判状态。[FTC案件时间线](https://www.ftc.gov/legal-library/browse/cases-proceedings/2123050-amazoncom-inc-rosca-ftc-v)

对资源较少的组织，优先迁移的是清晰的客户承诺、决策分级、单件成本拆解和停止低效投入的权限。只有当需求规模、资金来源、人才和供应能力都有证据时，才讨论多业务基础设施。尚缺的重要证据包括广告独立利润、Prime完整损益、关闭项目总投入、卖家渠道净回报及员工长期负荷。
