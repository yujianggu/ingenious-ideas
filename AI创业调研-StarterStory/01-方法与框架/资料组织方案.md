# 资料组织方案

更新：2026-09-20。适用于多来源创业研究，创意稳定编号、证据按来源登记。

## 选择：以创意为主线，来源与决策分层

当前最合适的是 Markdown 文件库：一份总览导航、一创意一档案、单独的来源索引和比较结论。已有 Git 仓库适合记录文字变化，暂时无需数据库或付费知识管理工具。

这不是适用于所有项目的唯一“最优”结构。选择依据是当前规模、可追溯性、维护成本与后续扩展需要。

| 方案 | 优点 | 主要限制 | 本轮决策 |
| --- | --- | --- | --- |
| 继续使用一个长文档 | 易开始、全文可搜索 | 多项详细内容相互挤占，证据更新容易遗漏 | 只保留作历史快照 |
| 每项独立文档＋总览＋来源索引 | 易链接、易比较、易更新，Git可追踪 | 需要统一编号与模板 | 采用 |
| 数据库或复杂知识图谱 | 适合大量记录与查询 | 录入、迁移和维护成本较高 | 需要频繁多维查询时再引入 |

## 设计原则与理论依据

本节是对现有设计的理论对应分析，补充于2026-09-20，不表示最初方案已按这些理论完整推导或经过效果验证。三类方法支持组织原则；具体目录、编号格式和工具仍是结合当前规模作出的实践选择。

| 理论或方法 | 核心思想 | 本资料库的对应设计 | 适用边界 |
| --- | --- | --- | --- |
| 数据规范化与实体建模 | 为对象保留稳定身份，减少重复记录导致的更新不一致 | 一创意一主档案、稳定B/C编号；同一创意的新来源补充原档案；地区与专题通过链接引用 | Markdown借用其设计思想，不具备关系数据库的完整性约束，也不声称符合某一范式 |
| 证据溯源（Provenance） | 记录资料的来源、产生过程与相关主体，使结论的依据可检查 | 来源编号、访问日期、就近引用；保留历史时期；区分来源陈述、研究推断和待验证假设 | 可追溯不等于来源真实；当前未实现完整的W3C PROV模型，也未对来源做独立审计 |
| 精益创业与验证式学习 | 通过提出假设、实验、测量和学习，减少创业中的关键不确定性 | 研究状态与验证状态分开；实验独立记录；优先级调整写明触发证据与停止条件 | 文档、访谈好评和案例收入不能替代本项目成交；小样本试点不能直接证明规模化盈利 |

### 为什么以创意为主线

本资料库要支持的决策是“某个创意是否值得继续投入”，因此以创意作为稳定研究对象。网站、国家和渠道提供不同观察维度，同一创意可以关联多个来源和地区。按来源网站重复建档，会使成本、定价和判断出现多个版本；保持一份当前主档案，可以减少这类更新不一致。比较表只摘录结论并链接主档案，摘录仍须在结论变化时同步维护。[Microsoft：数据库设计基础](https://support.microsoft.com/en-us/access/database-design-basics)

### 为什么分开保存来源、判断和实验

“创始人自述收入”“研究者推测存在需求”“本项目实际收到付款”具有不同的证明范围。将来源、判断和实验分别记录并相互链接，才能追问结论来自哪里、适用于哪个时期，以及什么新证据会使结论改变。W3C PROV以实体、活动和主体描述溯源信息，为这种可检查性提供了参考；事实、推断、假设的标注是本资料库的具体规则，并非PROV规定的分类。[W3C：PROV概述](https://www.w3.org/TR/prov-overview/)

### 为什么组织流程最终指向验证

资料积累应服务于减少关键不确定性。创意档案记录当前假设，验证记录保存执行条件和实际结果，比较与复审说明据此作出的决策，构成“假设—实验—学习—调整”的循环。这对应精益创业的Build–Measure–Learn与验证式学习。验证可能使创意退回补证或暂停，不要求所有创意依次进入开发。[精益创业：方法与原则](https://theleanstartup.com/principles)

## 工具选择与适用边界

Markdown＋Git、数字目录和To C／To B分类属于当前的工程选择，以上理论不能证明这些形式唯一或最优。Markdown便于阅读和链接，Git保存已提交的版本变化；两者不会自动保证来源可信、引用完整或比较结论同步。

地区、客户、渠道与交付方式是交叉维度，文件夹无法同时表达全部关系。当前通过稳定编号、统一字段和交叉引用维护；如果频繁需要多维筛选、批量更新或自动检查关系，应评估结构化索引或数据库，迁移时保留原编号和来源链。是否升级工具，以实际检索和维护问题为依据，不以档案数量单独决定。

## 组织效果的评价标准

以下是后续检查标准，尚无使用测量结果，不代表已经通过验收。新增研究批次或大幅调整目录后，可选取跨来源、跨地区及发生过结论变化的创意作检查；记录样本编号、检查日期、发现的问题和修复结果。

| 检查项 | 检查方式 | 通过条件 |
| --- | --- | --- |
| 当前判断可找到 | 从README进入指定创意，查找当前状态、建议和未知项 | 能确定唯一主档案；历史复审的时间与范围不会被误认为当前结论 |
| 结论可追溯 | 从关键判断反查引用及来源记录 | 能找到原始链接、访问日期及证据支持范围；自述与推断有明确标记 |
| 更新不分叉 | 抽查同一创意在主档案、比较表和地区专题中的记录 | 完整产品判断只维护于主档案；摘要与其一致，差异有地区或时间说明 |
| 决策变化可解释 | 对发生过优先级变化的创意检查变更记录 | 能说明原判断、新判断和触发证据；Git差异之外也有可读的修改理由 |
| 计划与执行可区分 | 检查验证文件中的状态和结果 | 计划明确标注未执行；执行记录包含日期、样本口径和真实结果，不以外部案例替代 |
| 维护成本可观察 | 记录查找依据和同步一次变更的耗时、漏改与失效链接 | 能识别重复出现的维护问题，据此调整结构；暂不设未经测量的耗时阈值 |

## 编号与信息归属

1. C、B分别表示To C、To B，后面的数字是稳定编号。文件名采用“编号-创意名称.md”，例如 `B05-培训材料自动出题.md`。编号不表示排名，标题或优先级调整不改编号；文件重命名时同步更新所有引用。新创意顺延编号，淘汰编号不复用。
2. 创意档案是产品判断的主记录；比较表只摘录结论，不重复全部成本与定价。
3. 来源编号采用 S-C01（Starter Story）、O-C01（官网）、R-C11-01（Reddit示例），同类多来源增加顺序号。来源索引记录访问日期和可证明的范围；具体事实在档案内就近链接。
4. 历史来源与当前官网都保留。历史营收不会因官网改版自动变成当前营收；旧产品停更或转向不等于历史案例造假。
5. 实验编号建议 EXP-C01-001，文件名建议 2026-09-19-EXP-C01-001-主题.md。未经执行的设计明确标“计划”，不填写虚构访谈、客户、销售额。
6. 只有真实产生截图、样例或其他附件后，才创建对应创意的附件目录。原始采访资料不重复复制到多个位置。

同一创意获得新来源时，更新原档案；只有客户任务、产品边界明确不同才新增编号。不会按来源网站重复建立创意库。Reddit新一轮使用C11—C20、B11—B20，原20项和既有历史复审保留范围标记。

## 更新流程

新增信息 → 登记来源与日期 → 修订对应创意档案 → 如影响排序则更新比较表 → 如有真实试验则保存独立记录。

状态依次可以为：桌面研究、待访谈、待付费验证、试点中、继续、暂停。当前档案均为桌面研究，没有把案例收入当成自己的验证结果。

每次改变优先级必须写明触发证据；不是因为文档更长就提高可信度。没有新增证据时不重复生成带日期的完整副本，历史版本优先交给 Git 管理。原始清单只做一次迁移，旧路径保留导航说明。
