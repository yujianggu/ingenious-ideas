# 商业产品分析框架

版本：1.2；日期：2026-09-19。

目标是回答：谁在什么情况下愿意购买什么结果，我们如何交付、触达客户并留下贡献收益，以及什么证据会推翻这个判断。

## 统一前提

本轮以个人或小团队为研究视角，尚无已确认预算、技能、渠道资源或目标地区。各项价格、用量、人工成本和实验阈值是测试假设，不是承诺报价、市场均值或成功概率。国内与海外适配均需要当地验证。

To C 以个人自身需求付费，To B 以组织业务结果付费。个体经营者为生产工具付款时可属于商业场景；不能用“用户是个人”自动判断为 To C。每个档案须交代所选择的场景。

## 新增：AI参与方式与上线依赖

研究范围包含“AI帮助创业者造出产品，产品上线后不必依赖AI”。不能只搜索AI产品或AI服务。To C / To B描述付款场景，与AI参与方式是两个独立维度。

每份新档案增加以下字段；已有档案在后续重评时补齐，不把未核查项默认填为低依赖：

| 字段 | 记录方式 |
| --- | --- |
| 客户购买的核心结果 | 不使用“AI”一词也能解释的价值 |
| AI参与环节 | 研发、内容制作、日常运营、用户核心功能，可多选 |
| 上线后AI依赖 | 核心必需 / 可选增强 / 核心无须 / 待核实 |
| 停用模型后的表现 | 哪些已售功能仍工作，哪些失效；不等于要求离线运行 |
| 产品交付方式 | 标准软件、数字资产、数据订阅、人工服务等 |
| AI降低成本的证据 | 区分实际开发记录、来源自述、本项目待验证假设 |

AI参与研发不自动证明产品容易实现；需要验证生成代码的可维护性、关键正确性、系统兼容、分发和售后。参考产品不是AI开发，也可以用于研究其购买场景与经营模式，但不得据此声称AI开发路径已被验证。

成本分开记录：前期研发与验证、每用户运行成本、持续维护与客服、获客与平台费用。研发阶段模型成本不机械摊成每次使用的API成本；没有运行时模型成本，也不代表交付边际成本为零。

详见[研究范围修正与补充方向](研究范围修正与补充方向.md)。Reddit来源另按[Reddit调研方法](Reddit调研方法.md)登记，不能把帖子热度或价格意向当作成交证据。

## 十二个分析模块

| 模块 | 必须回答的问题 | 合格输出 |
| --- | --- | --- |
| 产品判断 | 值不值得进入下一步？依赖什么资源？ | 有前提的建议，说明不适合什么情况 |
| 案例与证据 | 哪些内容实际被来源支持？ | 案例时期、来源类型、冲突与缺口 |
| 客户与购买 | 使用者、付款者、决策者是谁？ | 狭窄客户群、触发事件、现有替代方法 |
| 价值与流程 | 用户从输入到获得结果经过什么？ | 输入、处理、验收、交付与后续行动 |
| 最小可售产品 | 第一笔钱对应什么交付？ | 有边界的交付物、非目标、AI/人工分工 |
| 商业模式与经济 | 按什么计费？每单或每月是否留下收益？ | 明确周期、用量、成本与压力情境 |
| 获客与留存 | 第一批客户如何找到？为什么再买？ | 具体渠道、试点方式、复购或留存机制 |
| 竞争与差异 | 为何不用现成产品、人工服务或通用AI？ | 可检验差异，不能只写“更便宜更智能” |
| 市场与风险 | 地区改变会影响什么？哪里容易失败？ | 渠道、支付、集成、交付等实际约束 |
| 两周验证 | 最便宜的证伪方式是什么？ | 样本、任务、时间、门槛、停止条件 |
| 未知项 | 什么尚不能判断，如何补证？ | 按对决策的影响排序 |
| 来源 | 读者能否回到原资料？ | 可点击链接与访问日期 |

## 事实、判断和证据等级

- **[事实]**：来源确实如此陈述；不等于陈述已经过独立审计。创始人称有收入，只能标为自述收入。
- **[推断]**：从已知事实作出的判断，例如客户可能更在意交付质量而非生成数量。必须写出理由。
- **[假设]**：尚未发生的产品设计、定价、成本、渠道、留存或实验门槛，需要测试。

证据按“能支持什么”分类，不用一个总分掩盖不同性质：

| 类型 | 可以支持 | 不足以支持 |
| --- | --- | --- |
| 官方产品/定价页 | 页面宣称的功能、展示的报价与套餐限制 | 实际效果、真实付费人数、利润 |
| 创始人访谈 | 创始人对某时期业务的叙述 | 经审计财务、当前状态、可复制性 |
| 平台汇编/估算 | 研究线索与带来源的估计 | 独立验证后的营收、产品现状 |
| 自己的访谈 | 被访者的流程、痛点、已有开支 | 整体市场需求、未来购买承诺 |
| 自己的付费试点 | 特定价格和条件下的实际购买与交付表现 | 大规模获客、长期留存与盈利 |

Starter Story 存在成功案例选择偏差。参考案例的存在可以产生假设，但不能说明同类创业的平均成功率。

## 单位经济的统一算法

单笔或月度贡献额 = 该周期收入 − 对应交付变动成本。

交付变动成本包括：模型与工具、可变基础设施、支付与平台费用、直接人工、打印配送、重试、退款或返工准备。人工按“小时×假设时薪”计入，即使由创始人自己完成。若已按净收款计算收入，不再重复扣同一退款。

扣获客后贡献 = 交付贡献额 − 归属于该订单或新增客户的获客成本。一次性接入费和每月订阅分开算，不能用首月大额接入费掩盖持续维护亏损。

贡献额**不是净利润**：尚未扣除全部研发、固定办公、非交付管理人工、税费等。若用某价格、成本和付费数量得到年度收入，仅称“情境”，不能称预测。

对每项至少问：人工时间或重试成本翻倍后还剩多少？免费用户的成本由谁承担？客户达到额度后如何处理？不要在没有长期留存数据时套用简化 LTV 公式得出确定估值。

## 市场规模与优先级

本轮不填写缺乏来源的 TAM 数字。下一步用可触达客户数量×可接受价格×实测转化或复购估计小范围机会；把客户数量的证据和估计方法写出来，再考虑扩大。

- **P1 候选**：可在资源前提满足时进入小规模付费验证，不代表已经验证。
- **P2 观察**：有产品逻辑，但交付、渠道、留存或竞争压力需要先厘清。
- **P3 补证**：关键商业证据或当前产品状态不足，先核查再考虑开发。

不用虚构的精确分数排列候选。优先级受个人资源影响，比较表给出资源匹配后的路径。

## 实验与结论

每个门槛都是预先设定的决策规则，初期小样本只用于发现明显问题。真实执行后记录分母：接触多少人、多少人符合目标、多少人看到报价、多少人付费和完成使用。两周能测试购买与交付，不能确认月度留存、长期获客和季节性。

明确哪些结果支持继续、哪些意味着调整交付或渠道、哪些会终止方向。阅读官网、注册免费账号或获得口头好评，都不等同付费验证。
