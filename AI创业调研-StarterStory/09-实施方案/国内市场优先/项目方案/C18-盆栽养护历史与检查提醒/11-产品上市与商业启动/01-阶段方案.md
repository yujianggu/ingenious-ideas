# C18｜11 产品上市与商业启动：阶段方案

版本：V4｜状态：设计方案，执行记录尚未产生。价格、工时和门槛仍为待验证假设。

## 本阶段任务

面向许可园艺社群或花店展示历史查找与恢复；59元明确支持周期和照片策略，代迁移另计；先验证恢复优势再扩大传播。销售准备可提前并行；实际启动前核报价、付款、交付、客服和退款全链路。

## 责任与衔接

商业／运营负责人负责，项目负责人验收。 姓名及计划日期在启动时登记；内部角色兼任不能替代客户业务签认。

R4b：市场承诺对应已验收能力，渠道与交易条件核验有记录；获客预算、首批容量和复盘日已确定。

## 本项目详细资料

以下内容从原方案按章节迁入，作为本阶段维护正文。跨阶段交付的相关要求仍需与下游阶段对应。

### 典型异议与处理

- “现有应用已经能备份”：当场比较同一恢复任务，若没有差异就暂停。
- “希望自动告诉我多久浇水”：说明当前是自定检查，不作养护判断。
- “所有照片都要原图”：重新评估容量和备份体验，当前压缩策略先明示。
- “不会迁移帮我做”：单列服务成本。

### 从意向到试单的动作

| 节点 | 要完成的动作 | 留存证据 |
| --- | --- | --- |
| 资格确认 | 对齐近期任务、输入与决策人 | 原流程摘要、排除项 |
| 小样比较 | 同任务比较现有办法与拟议结果 | 差异及双方总耗时 |
| 完整报价 | 按实施方案给出金额、额度、交付和退出条件 | 范围版本、客户明确回应 |
| 启动确认 | 核实际可交付状态、输入齐备与约定付款节点 | 输入确认、真实交易凭据 |
| 交付验收 | 对照第三份文件，客户明确通过或退回 | 成果版本、验收意见 |
| 后续观察 | 按项目任务频率复用、续费或转介绍 | 使用记录与新付款分开 |

同一轮先保持原报价，记录拒绝原因；确需折扣时单独标为折扣样本，不当原价转化。客户缺输入则暂停排期。售前承诺只包含当前报价范围，不将未来愿景写进订单。付款、发票、退款和发布渠道在真实交易前按实际采用方式核验，此处不假定已具备条件。

## 上市与运营衔接卡

| 项目 | 本项目要求 |
| --- | --- |
| 首选渠道实验 | 许可园艺社群或花店；实际外部联系另按授权执行，当前仅为方案 |
| 首批容量 | 5名用户从10盆起步，至少两周真实检查观察；未获R5扩量决定前不扩承诺 |
| 销售材料 | 一页任务说明、脱敏或明确虚构的对照样品、完整报价、范围与验收清单、上手说明 |
| 启动前演练 | 合格线索→完整报价→购买确认→收款核对→开通或交付→客户验收→求助／退出；测试交易不得记真实收入 |
| 核心指标 | 自主录入恢复人数／尝试人数；历史与照片完整性；提醒异常按设备归因；迁移及支持小时；付款与退款；分子、分母、窗口和证据记录到T01 |
| 发布阻断项 | 未提示的数据丢失、恢复覆盖原库或照片缺失被当完整；发现后暂停受影响流程，修复复验再恢复 |
| 经营停止与调整 | 按商业模式与可行性、运营复盘阶段的停止门槛；真实贡献为负或需要长期代操作时先重估范围／价格／交付形态 |
| 发布后职责 | 运营负责人接收资产、支持窗口和故障台账；专业问题由指定审核人处理，缺人则限制服务 |
| 结项后收益 | 交付结项与商业验证分开；发起人指定收益负责人，按至少两周真实提醒观察和完整恢复；迁移任务不足则延长，不用植物存活率归因安排复查 |

所有成本与数量目前为计划假设；R1—R5均未执行。完整观察后才填写继续／调整／停止，不将“文档完成”写作项目成功。
