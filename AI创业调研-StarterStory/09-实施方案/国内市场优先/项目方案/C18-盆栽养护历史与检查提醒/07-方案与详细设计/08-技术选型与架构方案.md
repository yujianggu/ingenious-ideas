# C18｜技术选型与架构方案

采用基线 V2｜2026-09-20｜用户已确认按推荐方案推进；技术路线已采用，产品实现与真实验收尚未启动，新增工时和现金预算未自动获批。

## 已采用决策与执行条件

采用 **Android 原生 Kotlin + Jetpack Compose + Room/SQLite + 系统照片选择器 + AlarmManager 非精确本地提醒**。用户已确认采用推荐方案，首版单手机系统确定为 Android；5 位试用者设备用于建立兼容矩阵，iOS 不在本版交付范围。

区别于以计算与表单为主的线材工具，本项目的难点是照片完整性、事件时间、通知权限和设备后台限制。单系统原生实现便于直接检查通知与进程状态。无需云账号、模型、植物诊断、自动浇水或服务器。

| 方案 | 适用条件与本轮取舍 |
| --- | --- |
| Kotlin/Compose/Room | 已采用；配备熟练 Android 开发者，集中投入本平台通知和恢复可靠性 |
| Flutter + sqflite + 本地通知插件 | 出现双平台付费验证并经范围变更后可重新评估；插件仍需面对原生系统权限和厂商限制，不会自动保证准时 |
| SwiftUI + SQLite + UserNotifications | 后续 iOS 需求通过范围变更时评估，保持相同事件与备份协议，另做审核和设备验证 |
| PWA/微信小程序 | 可做日记样品或获客入口；当前不承担用户离线档案、完整照片恢复和系统日提醒主产品承诺 |

备选仅供新市场证据、实测不可接受障碍或明确的平台范围变更时重新评估；需记录影响与决定，不是本轮仍可任意切换的路线。最低系统、依赖版本及设备矩阵仍须实测冻结。

## 模块与用户需求映射

`Compose 界面 → 事件/计划命令 → Room 事务 + 私有照片文件 → 到期查询 → 系统通知调度器`。Repository 封装存储；ViewModel/StateFlow 更新界面，协程在 IO 调度器处理文件。通知是计划的派生动作，事实历史独立保存。

| 需求 | 技术实现 |
| --- | --- |
| R01/R06 多植物 | 植物 UUID、名称、位置、归档；同名允许，改名不改主键，列表与档案使用同一已保存状态 |
| R02/R04 实际事件 | 检查、浇水等四类用户自定事件；稳定 command_id 防重复；发生时间与记录时间分开 |
| R03 检查与延后 | 下次检查日期由用户设定；每天一条汇总到期提示；延后只改计划，不伪造浇水/检查事件 |
| R05/R07 恢复历史 | 植物、事件、计划、照片完整打包；预览植物数/事件数/照片数后切换；拒绝缺照片的完整恢复 |
| A01/A02/A07 | 禁通知仍显示到期列表；时区变更重算未来调度；归档取消该植物未来检查计划 |

模型：`plant(id,name,location,archived)`；`event(id,plant_id,type,occurred_at_utc,local_datetime,zone_id,recorded_at,command_id)`；`photo(id,relative_path,sha256,bytes,mime,event_id/plant_id)`；`check_plan(id,plant_id,local_date,revision,status)`；`notification_job(id,plan_revision,scheduled_at,state,permission_state)`；`metadata(schema_version,dataset_revision)`。所有记录外键可校验，照片路径只允许应用相对路径，禁止备份包路径穿越。

历史事件保留原时区与当地日期含义，旅行不会改写过去记录。检查计划按用户当前所在地日期显示；发现时区改变时提示并重排未来提示，已发生事件保持原值。用户手工记录未来事件时先提示确认；手机时间不是可信服务器时间，不把本地日志称为防篡改证据。

## 通知策略与失败恢复

采用每天一次、用户选择大致时段的非精确本地提醒；系统通知只表达“有植物待检查”。不申请精确闹钟权限、不依赖 FCM/Google Play 服务，也不以后台常驻和忽略省电作为默认要求。Android 13 及以上通知需运行时权限；在用户主动启用检查提醒时说明并请求，拒绝后不重复打扰。

AlarmManager 的实际执行受系统省电、设备状态和厂商策略影响，**不承诺准点或必达**。若业务以后要求分钟级准时，应重新定义产品边界和平台方案，不能靠一行插件配置对外承诺。正常状态只显示“已安排”，没有可靠回执不得标“已送达”；通知被点击可记“已打开”，也不等于已检查。

重启、应用更新、时区变更与重新打开应用时核对调度状态，按当前数据库重建下一次汇总；强制停止期间可能无法提醒，重新打开后首页继续显示全部到期任务。归档/延后通过 revision 使旧计划失效；系统触发时再次查数据库，避免旧通知带回已归档植物。通知失败不影响事件记录或照片保存。

## 照片、备份和恢复

通过 AndroidX Activity Result 的照片选择接口导入；设备没有 Photo Picker（含无 Google Play 服务的旧系统）时回退到 ACTION_OPEN_DOCUMENT。回退场景由应用再次限制图片数量、大小与类型，不依赖 Google 组件补装。[官方兼容说明](https://developer.android.com/training/data-storage/shared/photo-picker)。

通过系统选择器导入指定图片，复制到应用私有文件；不依赖外部相册路径长期不变。首版建议保存明确标识的压缩副本（候选上限长边 2048 像素），原图是否另存由用户验证后决定；不可宣称压缩副本是原图。用临时文件写入、校验并重命名，再提交引用；崩溃遗留临时文件可清理，已引用照片不自动清理。

备份格式 ZIP：manifest、版本化逻辑 JSON 数据、照片文件及逐文件 SHA-256。备份短暂冻结业务写入，在同一读事务导出一致数据并锁定照片引用；照片文件作为不可变对象，完成复制/校验前不清除。不要直接复制打开中的 SQLite `.db`（可能存在 WAL 未合并数据）。可用 SQLite online backup 生成快照，但与照片仍须同一 manifest 校验；本项目优先逻辑导出以便未来跨平台迁移。

恢复先限制压缩包体积/展开总量/条目数、防止路径穿越和压缩炸弹，再检查 schema、唯一 ID、外键、计数与所有照片摘要，装载临时数据库与临时图片目录；预览后复核 dataset_revision，用户确认再切换“数据集指针”。切换前原库/原图片保留为一份回滚数据；断电重启根据指针选择完整数据集，禁止数据库已切换而图片仍指向旧库。损坏、缺照片、不支持版本、空间不足均拒绝，不部分覆盖。恢复成功后清空旧设备通知状态，按新机权限重排提醒。

外部备份始终以带时间和随机标识的新文件名创建，不打开旧备份URI截断覆盖；先在私有目录生成完整包再写到新目标，写后校验成功才提示完成，provider中断可能留下不完整的新文件但旧文件不受影响。

备份导出到用户选择文件位置；取消选择不算失败保存，写满只损坏未完成临时导出，不覆盖旧备份。无云账号不等于数据不会丢，卸载前需要用户主动保存到应用外；App 默认不加入第三方分析或照片上传。

## 构建分发、许可与平台范围

固定 Kotlin、Compose、Room 和 Gradle 版本及依赖校验；Android Studio 构建签名 APK，渠道要求其他格式时单独输出。候选 Android 10 起测，最低支持版本由所选工具链与真实设备确认；至少覆盖一个接近原生环境和两家国内厂商设备的省电、权限与重启路径。HarmonyOS 原生应用不是 Android APK 的同义词，首版不顺带承诺支持，确认需求后独立选型与估算。

国内分发选具体商店后逐项核对账户资格、上架材料、隐私披露和更新渠道，本轮未完成上架审查；测试 APK 与正式发布要保管同一签名身份。首次预算只覆盖已有测试设备的内测，不预设商店已获批准。无服务器固定运行费；依赖构建缓存可离线复用，运行期不依赖外网服务。

Kotlin 与 AndroidX（Compose、Room）采用 Apache-2.0，SQLite public domain；发布包附开源许可和适用 NOTICE，SDK 与商店分发另受对应协议约束。优先用系统照片选择与标准 ZIP/摘要能力，避免为简单本地功能引入商业图像 SDK；新增插件逐个核对许可证。备选 Flutter 本地通知插件为 BSD-3-Clause，仍需按其原生平台限制验证。

## 分阶段估算与验收

假设 1 名熟练 Android 开发者、可借用三类真机、每周 20 小时；以下非报价。原 45 小时/约 3800 元研发情境不能保证正式照片恢复与通知兼容；首两周 40 小时/500 元现金限于用户/技术验证。

| 阶段 | 工时 | 出口（待实际测试） |
| --- | --- | --- |
| 样品与系统验证 | 12–20 | 5 位用户提供 Android 目标机型与系统样本；授权拒绝、断网、锁屏各跑一次 |
| 档案/事件/照片 | 32–48 | 10 盆实际使用闭环、重复命令不新增事件；检查不自动记录浇水 |
| 恢复与调度 | 32–48 | 备份损坏、缺图、写满、恢复中断、权限拒绝均保持原数据；计划和历史不混用 |
| 真机长期观察/发布 | 24–40 | 100 盆容量样本与至少两周使用观察；三类设备记录通知延迟及失败解释 |

合计 100–156 小时，约 5–8 周；按内部 100 元/小时示例为 1–1.56 万元人工机会成本。另预留 300–1500 元测试/分发现金情境，不含购机及待核渠道费用，维护每月另估 2–4 小时。若设备或实施能力不足，补齐资源并重估投入，不能自动变更平台或用预算压力省去完整恢复测试。

工程验收目标：100 盆/10000 事件样本首页到期查询 <500 ms；1000 张压缩照片、总量 1 GB 的备份恢复以全部摘要一致为硬门槛，耗时/峰值空间记录后再承诺，不拍脑袋承诺几秒完成。对 50 次随机提交点强杀、10 次恢复切换点中断，已提交事件不丢失且能选回完整数据集。通知验收记录计划时间/实际观察时间/权限/省电/系统版本，允许平台延迟但禁止界面虚报送达。以上为测试计划，并未执行。
