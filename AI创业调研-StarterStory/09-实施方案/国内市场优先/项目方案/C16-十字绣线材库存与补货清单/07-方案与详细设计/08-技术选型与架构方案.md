## 已采用决策与执行条件

采用 **Flutter + Dart + sqflite/SQLite**，首版离线手机应用、单品牌、一个活动项目、多色号库存。用户已确认采用推荐方案，首发固定为 Android；5 位试用者设备用于确定最低系统和兼容矩阵。保留同一业务逻辑未来复用的空间，不同时承诺两平台。

本项目核心是表单、半束运算、库存流水与文件导入，平台耦合较低。Flutter 的价值是这部分规则和界面可复用；sqflite 是 Flutter 官方 SQLite 教程使用的方案。无需云账户、服务端、AI、推送或摄像头。

| 方案 | 选择条件 | 本轮取舍 |
| --- | --- | --- |
| Flutter + SQLite | 小团队已有 Dart 能力，未来可能服务第二手机系统 | 已采用；当前只交付 Android，其他平台仍需独立范围变更与验证 |
| Kotlin + Compose + Room | 团队只熟悉 Android、确定至少一年只做 Android | 仅作为后续存在不可接受的实测技术障碍时的变更备选，不因人员偏好自动替换 |
| PWA/网页 | 低成本录入样品、验证单位与清单 | 保留现有原型；不把浏览器会话存储当正式库存库，手机文件往返需单独验证 |
| 微信小程序/桌面 | 获客入口/大量录入有明确验证 | 不作为首版主存储载体；当前核心是个人离线库存而非社交分发或桌面批量作业 |

备选仅供新市场证据、实测不可接受障碍或明确的平台范围变更时重新评估；需记录影响与决定，不是本轮仍可任意切换的路线。最低系统、依赖版本及设备矩阵仍须实测冻结。

## 需求映射、架构与数据

`表单 → Dart 领域命令/整数校验 → Repository → SQLite 事务 → 库存与清单查询`。状态使用 Flutter 自带 ChangeNotifier/ValueNotifier 起步，业务规则独立纯 Dart 模块；不先引入复杂事件总线或跨项目平台。CSV解析和恢复校验在工作 isolate 完成，结果经主存储事务提交。

| 用户需求 | 技术实现与不变量 |
| --- | --- |
| R01 多色号、前导零、未知余量 | `color.code TEXT`，`UNIQUE(brand_id, code)`；库存状态 known/unknown 与数量分离，未知数量为 NULL，不能默认 0 |
| R02 半束需求与缺量 | 库存/需求存整数半束数：1.5 束存 3；需购=max(need_half-stock_half,0)；只允许精确半束输入 |
| R03 采购与撤销 | 命令 UUID 唯一；库存变化、流水和清单版本在同一事务；撤销是关联原流水的补偿记录 |
| R04 实际耗用 | 以实际量提交，不按项目需求自动扣；库存版本校验和非负约束，待核库存禁止扣减 |
| R05 备份、R06/R07 连续使用 | 全品牌当前范围下所有色号、项目需求及历史一起备份；恢复先预览再整库替换；输入草稿不能伪装为已入账 |

建议表：`brand(id,name)`；`color(id,brand_id,code)`；`inventory(color_id,known,half_qty,revision)`；`project(id,status)`；`project_need(project_id,color_id,half_qty)`；`movement(id,command_id,color_id,delta_half,kind,reverses_id,created_at)`；`import_batch(id,source_digest,status)`；`metadata(schema_version,dataset_revision)`。数据库强制外键、非负数量、唯一色号；单活动项目规则由事务服务维护，首版不做多项目占用分配。

缺线清单带输入 revision；改库存、需求或切到“待核”立即使旧清单失效，不能用旧计算结果入库。撤销仅允许该色号原入库后没有后续变化的安全情形，否则转为明确的库存核对，不盲目减去旧采购量。重复点击带同一 command_id，事务只生效一次；数据库提交成功后才显示成功。

## CSV 导入与备份恢复

CSV 首版只接本项目模板 `brand,code,stock_status,stock_bundles,need_bundles`，UTF-8 可带 BOM；色号全程字符串，不做数值转换；不自动猜品牌、编码或四舍五入。非法行、重复色号、品牌不符、半束小数错误逐行预览，用户修正后整批提交，不能悄悄跳过错误行。相同批次摘要重复导入必须提示并避免重复入库；库存导入定义为核对后的余额更新而非采购流水，已有色号冲突逐项确认。

备份采用 SQLite 读事务下的一致性逻辑 JSON 导出，内含 schema_version、记录数、流水、单位版本、清单和校验摘要；不直接复制运行中 `.db`。写临时输出完成后再通过系统文件选择器创建带时间与随机标识的新文件，禁止打开旧备份URI截断覆盖；目标写入完成并校验后才提示成功。provider中断可能留下不完整的新文件，但旧备份不被覆盖。JSON 摘要检测意外损坏，不声称可证明外部文件未被恶意重写。

恢复：限文件大小→解析→schema/数量/外键/唯一性/半束整数及流水一致性验证→临时 SQLite→显示替换范围→比对预览时 dataset_revision→确认切换。预览后发生新编辑则要求重选；取消或错误保留原库；切换前保存回滚副本。旧原型 V2/V3 JSON 仅经显式迁移器读取：限制只恢复本项目已知格式，旧单条不覆盖其他色号，重复色号拒绝。将来未知版本直接拒绝，不猜测兼容。

Android 使用系统 Storage Access Framework 读写用户选择的文件，不申请全盘管理权限。若用户选云盘 provider，说明是用户主动选择的输出位置，产品本身不上传；可选本机下载目录。应用私有库不作为卸载后的恢复保障，首次形成有效库存后提示导出备份。

## 分发、依赖与维护

固定 Flutter 稳定工具链、Dart 与 sqflite 锁文件，依赖更新逐次通过迁移/恢复回归。Android 使用签名 APK 测试与对应国内渠道要求的产物，不依赖 Google Play 服务、Firebase 或在线登录。Android 首发以 Android 10 作为候选最低版本起测，最终以 SDK/插件支持范围与试用设备决定；商店账户、上架材料、隐私与渠道政策在选择具体商店后核对，当前不假定已具备。国内构建依赖下载可按 Flutter 官方中国指南配置可信镜像并保留完整性与锁版本；正式 App 可全程断网运行。

Flutter BSD-3-Clause、sqflite BSD-2-Clause、SQLite public domain；分发保留对应版权与许可。CSV 解析器优先自带小型已审计库，新增包前核对许可和维护状态，不在此预设不存在的许可证批准。无定时任务、广告、遥测 SDK；备份格式独立版本便于未来原生实现读取。

## 阶段、成本和可测验收

假设 1 名熟练 Flutter 开发者、已有 Android 真机，每周 20 小时；以下为规划范围，非报价。原 40 小时/约 3400 元研发情境不能当正式完整实现预算；首两周 40 小时/500 元外部现金仍只用于验证。

| 阶段 | 工时 | 出口（工程目标，未实测） |
| --- | --- | --- |
| 样品验证 | 8–16 | 5 人用 20 色样本确认半束/待核/品牌规则，拿到真实 CSV |
| 库存与流转 | 24–40 | 前导零、未知值、非法小数、重复入库、撤销后续变化均有自动化用例 |
| CSV/备份/迁移 | 24–32 | 损坏/重复色号/未来版本均不改原库；干净安装往返数量和流水一致 |
| 真机与分发 | 16–24 | 两款目标真机离线完成全过程；强杀、磁盘不足、文件权限取消不丢已提交库存 |

合计 72–112 小时，约 4–6 周；内部 100 元/小时仅作机会成本示例为 7200–11200 元。已有设备时另预留 200–1000 元现金用于测试/渠道杂项，不含购机与待核渠道费用；无固定云费。维护另按每月 1–3 小时估算。需要第二平台时另估 24–48 小时适配与真机验证，不因 Flutter 可编译就标为已支持。

容量目标：首用 20 色，工程测试用 1000 色/10000 条流水/1000 行 CSV 作为压力样本而非对外新增承诺；目标真机清单计算 <200 ms、1000 行导入预览 <2 s（后台解析），导入可取消。每次备份恢复后比较所有库存、需求与流水，不只比较总条数。UI 输入显示 0.5，存储只存整数；随机合法半束序列验证无负库存、无重复命令入账。
