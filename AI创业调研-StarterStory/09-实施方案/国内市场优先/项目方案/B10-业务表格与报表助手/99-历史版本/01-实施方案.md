# B10｜业务表格与报表助手：实施方案

> V3阶段导航：见[全生命周期主计划](00-全生命周期主计划.md)。本文件保留商业参数或执行细则；阶段顺序、产出物与评审按主计划执行，原数字仍为待验证假设。

版本：V1（保留原方案；配套执行细则V2）｜2026-09-20｜中国优先顺序2｜形态：模板接入＋持续报表服务。以下均为待验证设计。

## 1. 商业定位与报价

买家是中国大陆的小型电商运营团队，管理2—5家店铺，固定同一平台导出数据。运营负责人使用并确认业务解释，店主付款；财务或指定人员确认金额口径。若只能取得不同平台、不同结构的零散资料，先不承接标准包。

卖点是按约定时间得到可核对的经营周报，附异常和来源；先比较客户现有Excel／WPS模板，证明减少了整理与核对总时间。不能只以图表数量或“AI洞察”报价。

拟议接入费3000元，一次固定模板和口径配置；月费1500元含4次周报。首次交易拆开接入验收和月包验收，明确付款节点，不用接入费掩盖月度亏损。小样只用一段授权脱敏数据，正式接入前给客户看结果结构。新增平台、新增业务规则、第五次报告另确认范围。

## 2. 产品内容与核心数据

P0输入为同一平台的订单、退款、广告三类固定文件，最多2—5店；一次接入冻结列名、数据类型、主键、时区、币种和时间区间。缺成本资料不输出“净利润”；缺广告文件则相应指标标不可计算。

交付工作簿至少含：经营摘要、按店／时间汇总、异常清单、明细追溯、口径字典、运行说明。任何关键数值能追溯到文件、行或确定性转换步骤。退款按发生期还是订单期、取消订单、平台费用和跨币种转换，由客户确认后冻结。

P0流程：收件校验→锁定输入批次→字段映射→规则计算→总额核对→异常处理→文字说明→复核导出。AI可提出映射建议和解释草稿，金额与比率由确定性规则计算。数据不能推出原因时只描述现象和待核假设。

P1才增加一个相同格式的新店铺；P2才讨论自动接口或客户自助平台。不做自动投放、税务判断或任意文件即时分析。

## 3. 获客和试单设计

通过允许招募的电商运营场景寻找8—12名运营人员，目标获得3套同平台脱敏样本。展示“退款跨期如何导致两张表不一致”的虚构例子，以实际核对能力获得演示机会。访谈最近一次周报由谁做、耗时、争议及批准预算的人。

同一份输入同时用原流程与新流程处理，计入客户复核时间。目标取得1个完整范围的付费试单；客户只喜欢图表但不愿为核对付费时，不提前做自助SaaS。

## 4. 交付SOP与验收

| 节点 | 动作 | 输出 |
| --- | --- | --- |
| 接入前 | 核样本、数据授权、责任人和缺失字段 | 输入字典与不可计算指标 |
| 接入 | 对历史一期生成样报，逐指标对齐客户基准 | 口径V1、样报V1、差异解释表 |
| 每周截止 | 收齐文件并冻结版本；迟交则重排交付日期 | 输入批次清单与校验结果 |
| 生产 | 去重、匹配退款、计算、核对、异常追踪 | 可复算工作簿与异常清单 |
| 复核 | 服务方先复核，客户负责人后验收 | 验收记录及版本号 |
| 月末 | 4次记录汇总，核人工与格式变化 | 月度交付报告、续用决定 |

建议输入完整后2个工作日内交付；客户3个工作日内集中反馈同一口径问题，沉默不自动当作验收。承诺内数值错误负责修复；业务口径变化走变更单。

关键数值与约定基准在共同精度内完全一致，所有差异可解释；订单重复、缺列、无匹配退款、负值、重复上传和时间跨界必须能识别。输入总额、转换后总额、输出汇总之间有对账桥梁。文件格式变化时失败关闭并提示，不静默错算。

## 5. 经营经济与产能

月包1500元减模型80、计算存储50、复核3小时×150、维护150、支付15、返工退款75，贡献680元；新增客户获客600元，首月月包扣获客仅80元。接入费扣8小时×150及支付30后贡献1770元，另计返工。

若每周多1小时修复，月增加600元成本，月贡献只余80元；因此格式变更不是免费赠送。若输入一直不稳定，可以转定制服务重新报价，不能继续把成本压进标准包。

每周20小时可用时，月80小时并非都能交付。先保留30小时用于销售、管理与维护，余50小时；理论50÷3约16个稳定月包，但尚未含接入和非预算沟通，初期最多2家，逐月用实际总工时限额。

## 6. 推进、停止与长期路线

前两周拿3组样本并验证口径；第3—4周接入1家付费客户；第5—8周完成连续4次报告；第9—12周接入第二个同类客户，核复用与续费。

继续条件：关键数字可复核、客户总耗时下降、月复核在3小时预算附近、第二家不必重新设计全部映射。无解释差异或反复口径争议先停交；第二家完全定制则保留服务定位，不自动扩大软件投入。
