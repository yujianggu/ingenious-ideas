## 结论与适用范围

采用 **Python + pandas + Decimal／整数分 + openpyxl + SQLite 的本地周报生产流水线**。交付形态为工作簿、口径说明和人工确认记录；客户不操作内部字段映射。首版按同一平台、2—5店、每月4次周报、初期最多2家客户设计。已有电脑、技术人员具备 Python 基础、小团队低现金投入是暂定假设，默认采用栈已确认，人员熟练度与运行条件待核。

资金和业务收益仍沿用原方案：接入3000元及1500元月包是待验证报价，首两周不超过40小时、外部现金500元是规划约束。先解决金额可复算和格式变更停跑，不把原型扩成客户自助 SaaS。

## 推荐组件及备选取舍

| 层次 | 首选 | 理由及边界 | 备选／启用条件 |
| --- | --- | --- | --- |
| 输入与清洗 | pandas 读取约定 CSV／XLSX，字段配置 JSON | 列名、类型及店铺身份显式验证 | 仅2—3份小样可人工工作簿；连续4周稳定后自动化 |
| 金额规则 | 标准库 Decimal 解析，按币种精度存整数最小单位 | 不用二进制浮点直接累计金额；舍入规则先签认 | 不选择 LLM 算金额；更大规模时评估数据库聚合 |
| 工作簿 | openpyxl 写明确值及来源索引 | 客户可复核；不依赖服务器执行 Excel 公式 | 已有授权的 Excel／WPS 用于人工打开复核 |
| 元数据 | SQLite + 不可变文件目录 | 单操作者、每次运行可追溯，运维轻 | 多人并发确立后再评估服务端数据库 |
| 文字摘要 | 首版人工；可选模型仅润色脱敏指标解释 | 数字必须来自冻结指标表 | 无 AI 也能完整出报 |

pandas 提供连接校验和匹配来源标识，可用来暴露不匹配行；它不会自动保证业务关联正确。[官方 merge 文档](https://pandas.pydata.org/docs/reference/api/pandas.DataFrame.merge.html)。openpyxl 可读写 XLSX，但本方案计算在 Python 内完成，工作簿不依赖公式缓存。[openpyxl 官方文档](https://openpyxl.readthedocs.io/en/stable/)。Decimal 能表达十进制数并显式控制舍入；金额须从规范化字符串构造，禁止先转 float。[Python Decimal 文档](https://docs.python.org/3/library/decimal.html)。

不选低代码报表平台作为首版核心，因为三表口径、退款归属及来源追溯尚未稳定；不选多服务 Web 架构，因为初期客户量无法摊薄账号、上传、托管和权限维护成本。若用户已有经过授权的稳定工作簿流程，可继续用其做业务基准，脚本与其逐项比对后替换。

## 组件与数据流

```text
客户三表与期间确认 → 人工收件清单 → 原件冻结+SHA256
 → 列与值校验 → 按店铺映射 → 退款先聚合 → 确定性指标
 → 差异清单 → 人员复核 → 版本化工作簿+口径说明 → 客户签认
```

原文件只读保留；每一行带 source_file_id、sheet、row_index。映射更改生成新 mapping_version，指标配置带币种、发生期、分母、空值和舍入规则。输入批次以客户、店铺、文件类别、期间及文件摘要查重；同内容改名不重新累计，同期间新内容须明确替代关系。重跑用新 run_id 和 report_version，旧版保留并标注被谁替代。

## 数据模型、边界与规则

- Client → Shop → ReportPeriod → InputBatch → Run → ReportVersion；关键记录均带 client_id。订单身份至少是 client_id + shop_id + order_id。
- RefundEvent 有独立事件 ID；缺稳定退款 ID时由源系统约定导出批次及行身份，并登记重复判断规则，不能凭金额相同删行。
- MetricValue 保存规则版本、值／不可计算原因、来源行集合。ReviewEvent 保存操作者、动作、原因、结果摘要及人工确认附件。
- 退款按店铺+订单聚合后与订单关联，验证关联基数，防止一单多退把订单金额放大。无匹配退款保留异常，不静默丢弃。
- 实收减退款只命名“实收减退款”，没有成本不输出净利润；缺广告标缺失和相关比率不可计算，不填0。分母为0显示不可计算。空订单键、NaN、无限金额、格式变化停止受影响计算。
- 客户运营负责人签认口径，交付人员运行及修复映射，客户指定复核人验收。脚本成功不等于人工或客户已签认。

## AI与人工的边界

首版模型调用可以为0。人工解释基于已计算指标；若增加 AI，只发送经许可的脱敏指标及口径，禁发订单个人信息，输出中的数字与指标 ID逐项对照，新增数字或因果结论转人工。模型不能修改字段映射、补缺金额或批准差异。

模型候选选择阿里云百炼 **Qwen Plus 系列的国内地域可用文本模型**，在样例评估后冻结具体模型 ID、地域、接口、参数和提示词版本；不在未评测时断言某个快照最优。官方文档提供结构化输出方式，但不同地域和快照的支持情况不同，因此不能仅凭系列名保证 JSON Schema 可用。实施前查实际模型能力，若不支持则使用文本／JSON输出加应用校验，最多2次受控重试后转人工，不自动换用境外端点。[百炼结构化输出](https://help.aliyun.com/zh/model-studio/qwen-structured-output)、[模型能力与地域示例](https://help.aliyun.com/zh/model-studio/qwen-plus)、[可用模型查询](https://help.aliyun.com/zh/model-studio/list-models)。结构正确不代表事实正确；来源校验和专业审核必须保留。调用超时不推进审核状态，重试按任务及候选批次幂等登记，费用单独累计。

## 计划成本与分阶段实施

以下为预算假设，非厂商报价，不新增订阅承诺。现有电脑和办公许可可用时无新增服务器月费；原月包模型80元及计算存储50元是每客户预留上限项，实际按用量记录，不因本地运行删去人工复核成本。原3小时复核×150元、维护150元等继续列账。首两周技术工作建议20小时以内，余下20小时留给收件、口径确认与客户验证；超出时先缩样本，不挤占核对。

1. 第1—4小时：取得三表和业务口径，做1店1周人工基准、明确退款时间归属。
2. 第5—12小时：实现映射、校验、计算和源行追溯；异常测试全部通过后扩到2—5店。
3. 第13—20小时：工作簿导出、独立复核、重跑及备份恢复演练；达到验收才交付首周。
4. 四周实际交付后才评估内部工作台；要有重复操作耗时记录和明确维护预算。

待核：数据授权和收件渠道、真实导出格式及规模、客户复核人、退款跨期口径、Excel／WPS兼容环境、人员 Python 能力、存储与保留时限。任何一项阻断验收都登记负责人，不假设已满足。

依赖许可：pandas 为 BSD-3-Clause（[官方许可](https://pandas.pydata.org/docs/getting_started/overview.html#license)），openpyxl 为 MIT（见其[官方首页](https://openpyxl.readthedocs.io/en/stable/)）。部署时对锁定版本及传递依赖重新核对。以上技术来源均于2026-09-20核查，未将文档展示版本当作本项目已安装版本。

上述20小时是本项目首轮技术验证的时间盒，只针对约定样本与受控人工操作，不是完整自动化工具的完工估时。验证后按真实格式、异常样例和操作人员能力拆解余下工作，单独确认后续研发及维护投入；未通过验收的步骤继续人工完成，不把时间用完视为可以正式交付。

## 部署、操作权限与恢复

首版由指定交付人员在现有电脑运行固定 Python 虚拟环境；依赖版本和文件摘要锁定，安装包来自官方分发并留档，客户原件不进 Git。SQLite 只存元数据、状态、索引；原件和导出文件按客户 UUID／任务 UUID／版本分目录，文件名不作为权限依据。单次作业领取锁，成功后事务提交状态，失败不覆盖旧交付。CLI 的任务参数必须匹配客户清单，导出同时校验 manifest 中的客户 ID、任务 ID 和全部文件摘要。

首版没有客户登录服务，也不把原型角色开关移作权限控制。客户通过约定收件渠道交资料，交付人员记录实际发送者及确认记录；本地 OS 账户仅授权交付人员，客户只取得本任务成果。多人同时编辑时再启动内部工作台评估，并增加服务端身份、逐任务授权、审计与并发控制；不得把 SQLite 文件放在共享网络盘上让多人直接写。

每天工作结束并在交付前做一次一致备份：SQLite 使用 Backup API，冻结的文件目录与摘要清单一同加密保存到独立备份介质；密钥单独保管。[SQLite 官方 Backup API](https://www.sqlite.org/backup.html)支持运行中数据库的一致备份，但附件一致性仍由作业冻结和清单校验实现。规划恢复点不超过一个工作日、恢复时间不超过4小时，属于待演练目标，不能当现成承诺。首单前在空目录还原，核对行数、文件摘要、旧版与最新状态，并实际打开交付文件。保留期限与删除周期在收件约定中确认；到期覆盖原件、派生稿和备份轮换，不假定删数据库就已删除全部资料。

不采购服务器、对象存储或自建 GPU。若客户约定需要国内云备份或多人远程访问，再单列地域、存储、访问费用及授权评审；本地方案不能推出“本地运行就没有模型外发”。任何模型调用前都需确认允许外发的字段与教材范围，去掉无关身份信息，密钥只在 OS 密钥库或受限运行环境保存。

## 依赖与维护规则

使用 Python 标准库与下述必要依赖，不引入微服务、向量数据库、自动代理编排或 Kubernetes。实现时固定经过用例验证的版本，不使用浮动 latest 作为生产依据。维护一份第三方依赖及许可清单；内部使用、打包分发和修改再分发的条件分别核查，保留版权通知。Python 使用 [PSF 许可](https://docs.python.org/3/license.html)，SQLite 核心为 [公有领域](https://www.sqlite.org/copyright.html)。API 服务遵循供应商服务条款，不能把开源模型许可当成商业 API 条款。
