2026-09-20，用户确认按推荐方案推进；本项目采用 **Python + pypdf／python-docx + SQLite + openpyxl 的教材出处与题包生产管线**。这是采用基线，不代表开发完成、真实验收通过或预算已批准。

备选方案仅在出现容量、兼容、人员或客户交付条件的实际证据后走技术变更；不再作为待用户重选的默认栈。具体依赖版本、模型快照、人员和实际报价在实施时核实。

## 结论与适用范围

采用 **Python 教材与题包生产管线：pypdf／python-docx 提取文字，标准库 JSON 校验和去重，SQLite 管题目版本，openpyxl 输出审题矩阵和客户约定导入格式**。AI生成候选，人工逐题审查和客户专家校准决定采用。首版仍是咖啡门店固定教材100题服务，10题样本计入100题、先确认10题再制作其余90题；不开发考试系统。

与报表项目不同，本项目的核心不是金额计算，而是教材出处和题目审核链。初期最多每月2包；暂按已有电脑、可用办公工具及小团队维护能力设计，技术人员能力与具体运行条件待核。

## 推荐组件及备选

| 环节 | 推荐 | 选择原因与限制 | 备选条件 |
| --- | --- | --- | --- |
| 教材收件 | 冻结文本PDF或DOCX，保留原件摘要 | 每题来源绑定确切版本 | 只有扫描件时人工录入已核章节；复杂OCR另估范围 |
| 文本提取 | pypdf、python-docx | 文本PDF按页；DOCX按标题+段落ID定位 | 不以DOCX动态页码作稳定来源；需页码时先冻结PDF |
| 题目生产 | Python按知识点批量调用候选模型或人工录题 | 小批次便于暂停、重做和逐题核查 | 无网络、无外发许可时全人工候选 |
| 校验 | JSON字段及枚举验证、标准化文本重复检查 | 无效答案、缺出处、重复ID可机器阻断 | 相似语义和双重否定交人工判断，不靠相似度直接删题 |
| 审题与交付 | openpyxl审题矩阵、固定CSV／XLSX导入适配器 | 一种导入格式可回读比对 | 不先建RAG平台、向量库或客户考试端 |

[pypdf官方说明](https://pypdf.readthedocs.io/en/stable/user/extract-text.html)明确文字提取不等于OCR；图像PDF无可用文字时拒绝自动出题，不能拿空文本调用模型。表格、分栏提取仍须抽查原页。[python-docx](https://python-docx.readthedocs.io/en/latest/)用于读写DOCX；来源位置由本项目建立段落标识，库不保证教材语义正确。

## 架构与数据流

```text
冻结教材及导入样本 → 章节/段落切分 → 知识点覆盖矩阵
 → 每知识点选定原文证据 → 10题候选 → 逐题审查 → 客户校准
 → 其余90题候选与逐题审查 → 格式导出 → 实际试导入及回读比对
 → 100题成包 + 答案出处 + 覆盖矩阵 + 验收记录
```

模型每次只看到该题候选所需的授权原文和知识点，不用外网补教材事实。source_locator由程序从预先登记的来源列表分配；模型返回的来源ID必须存在，引用文字必须匹配对应原文。引用存在仅证明“找得到”，答案是否被该句支持仍由人审。原教材冲突时冻结受影响知识点，等待客户专家澄清后出新教材版本。

## 数据模型与审核规则

- Client → TrainingTask → MaterialVersion → SourceSegment；教材有SHA256、原页／段落定位、解析版本和人工抽查记录。
- KnowledgePoint记录计划题量和是否明确不考；QuestionVersion记录题型、题干、选项、答案、解析、知识点及出处ID，历史不可覆盖。
- ReviewEvent记录审题人、结论、原因、教材版本；Calibration记录10题版本集合及客户确认。ExportPackage绑定100个已审题版本和导入映射版本。
- 题目任何改动使该题回到待审；教材变化使关联题回到待定位和待审。10题确认后若教材或题型边界变化，先重新校准，不沿用旧通过状态。
- 每个任务和导出包带client_id和task_id；不同教材同名、不同客户同主题仍独立。培训负责人提供材料，审题人逐题签认，客户专家解释教材并确认采用；员工不进入生产台。
- 单选答案必须恰为一个有效选项，多选答案为非空有效选项集合；缺解析／出处、重复题号、知识点空白（未获客户批准）阻断出包。

## 模型与人工作业

模型候选选择阿里云百炼 **Qwen Plus 系列的国内地域可用文本模型**，在样例评估后冻结具体模型 ID、地域、接口、参数和提示词版本；不在未评测时断言某个快照最优。官方文档提供结构化输出方式，但不同地域和快照的支持情况不同，因此不能仅凭系列名保证 JSON Schema 可用。实施前查实际模型能力，若不支持则使用文本／JSON输出加应用校验，最多2次受控重试后转人工，不自动换用境外端点。[百炼结构化输出](https://help.aliyun.com/zh/model-studio/qwen-structured-output)、[模型能力与地域示例](https://help.aliyun.com/zh/model-studio/qwen-plus)、[可用模型查询](https://help.aliyun.com/zh/model-studio/list-models)。结构正确不代表事实正确；来源校验和专业审核必须保留。调用超时不推进审核状态，重试按任务及候选批次幂等登记，费用单独累计。

推荐评测集用10道已由专家确认的校准题及故意含冲突的教材片段，记录出处真实性、答案可采用率、人工修改时间和调用成本；模型升级重新跑评测。模型不获文件写入或发布权限；教材中出现的“忽略规则”等文字只当材料内容。超限、失败或格式错误均回到人工录题和相同审题表，不跳过校准。

## 需求落实与验收

| 需求 | 技术落实 | 计划测试 |
| --- | --- | --- |
| R01、N01 | 教材版本与来源定位 | 新教材页码漂移后旧题被标待定位；错版本不能交付 |
| R02、A01—A04 | 候选校验+逐题审查 | 仅换主语的重复题人工退回；教材冲突、双重否定、多选漏答均阻断采用 |
| R03、R04 | 10题校准及版本反馈 | 未确认10题不能生产正式其余90题；退回后旧确认失效 |
| R05、N02、N03、A06—A07 | 数量/覆盖/导入验证 | 最终100题（包括10样题）均有审查记录；特殊字符、答案、解析导入后逐项一致 |
| R06、R07 | 多任务版本隔离 | 同主题不同教材不串用；改稿保留旧版且重新审查 |

初交可采用率≥90%是原业务目标；最终100题均需达到约定质量，不以自动校验通过代替业务验收。没有目标系统试导入机会时，只能标“格式预检通过，实际导入待客户确认”，不能宣称可用题包已验收。

## 分阶段实施与成本

计划首两周技术投入最多18小时：4小时取得教材和真实导入模板，6小时建立来源切分与校验，4小时建立导出及回读，4小时恢复演练及边界样例；其余22小时给校准、审题和客户沟通。完成10题真实校准再排其余90题，超出40小时则缩试点或改计划。

预算沿原方案：每100题模型60元、存储20元是预留，不是实时厂商价格；审题5小时×120元、导入沟通200元、模板接入100元等不得被“自动出题”删掉。首两周外部现金500元的限制仍适用，先使用现有设备，不采购OCR订阅、向量库或GPU。实际模型费按输入/输出token、重试和实际单价登记；超过预留就暂停扩大批量，重新算贡献。额外返工4小时×120元会使原获客后贡献转负，故优先减少歧义和导入返工。

待核：教材是否允许外发、可提取文字比例、教材页数及图表复杂度、知识点责任人、客户实际导入模板与试导入机会、题型范围、审题能力、模型在国内地域的实际可用ID、保存期限。

## 部署、操作权限与恢复

首版由指定交付人员在现有电脑运行固定 Python 虚拟环境；依赖版本和文件摘要锁定，安装包来自官方分发并留档，客户原件不进 Git。SQLite 只存元数据、状态、索引；原件和导出文件按客户 UUID／任务 UUID／版本分目录，文件名不作为权限依据。单次作业领取锁，成功后事务提交状态，失败不覆盖旧交付。CLI 的任务参数必须匹配客户清单，导出同时校验 manifest 中的客户 ID、任务 ID 和全部文件摘要。

首版没有客户登录服务，也不把原型角色开关移作权限控制。客户通过约定收件渠道交资料，交付人员记录实际发送者及确认记录；本地 OS 账户仅授权交付人员，客户只取得本任务成果。多人同时编辑时再启动内部工作台评估，并增加服务端身份、逐任务授权、审计与并发控制；不得把 SQLite 文件放在共享网络盘上让多人直接写。

每天工作结束并在交付前做一次一致备份：SQLite 使用 Backup API，冻结的文件目录与摘要清单一同加密保存到独立备份介质；密钥单独保管。[SQLite 官方 Backup API](https://www.sqlite.org/backup.html)支持运行中数据库的一致备份，但附件一致性仍由作业冻结和清单校验实现。规划恢复点不超过一个工作日、恢复时间不超过4小时，属于待演练目标，不能当现成承诺。首单前在空目录还原，核对行数、文件摘要、旧版与最新状态，并实际打开交付文件。保留期限与删除周期在收件约定中确认；到期覆盖原件、派生稿和备份轮换，不假定删数据库就已删除全部资料。

不采购服务器、对象存储或自建 GPU。若客户约定需要国内云备份或多人远程访问，再单列地域、存储、访问费用及授权评审；本地方案不能推出“本地运行就没有模型外发”。任何模型调用前都需确认允许外发的字段与教材范围，去掉无关身份信息，密钥只在 OS 密钥库或受限运行环境保存。

## 依赖与维护规则

使用 Python 标准库与下述必要依赖，不引入微服务、向量数据库、自动代理编排或 Kubernetes。实现时固定经过用例验证的版本，不使用浮动 latest 作为生产依据。维护一份第三方依赖及许可清单；内部使用、打包分发和修改再分发的条件分别核查，保留版权通知。Python 使用 [PSF 许可](https://docs.python.org/3/license.html)，SQLite 核心为 [公有领域](https://www.sqlite.org/copyright.html)。API 服务遵循供应商服务条款，不能把开源模型许可当成商业 API 条款。
