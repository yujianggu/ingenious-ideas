# C13｜客户开发与成交

版本：V2｜以下为拟执行步骤和脚本，尚未联系客户。

## 1. 首批客户与购买角色

使用Mac、准备合并2—4块外置硬盘、积累家庭照片的个人。先限普通文件目录，不把系统相册库、云盘占位文件和专业素材引用当成普通文件自动处理。买家本人操作，设备与文件系统组合在首批招募时记录后再决定支持范围。

筛选时分别记录任务是否近期发生、是否能展示原流程、是否有最终确认人、是否看过完整报价。只有兴趣但无真实任务的线索放观察池，不计入合格买家。

## 2. 渠道与名单动作

在允许招募的摄影与家庭资料整理场景找8—12人，争取5人展示当前工具。用模拟文件和报告展示，不要求上传家庭照片。优先招募近期真的整理硬盘的人，单纯担心未来丢照片但没有任务的人不计合格试用。

名单字段：客户代号、公开业务入口、筛选理由、当前工具、联系人角色、沟通许可、最后一次进展、退出原因。先记录可联系入口，再按渠道规则沟通；本文件不是已获客户许可的名单。

## 3. 一次访谈怎么做

前5分钟确认岗位、任务和资料使用范围；中间15分钟让对方演示最近一次真实任务；最后10分钟核对总用时、付款人与试点条件。先观察旧流程，后展示方案，避免用功能清单诱导回答。

1. 最近为什么要合盘，实际有几块盘和多少文件。
2. 上次怎样确认某张照片在哪些盘。
3. 用过什么免费工具，哪个结果看不懂。
4. 是否能同时连接需要核对的盘。
5. 只给只读报告而不自动删除是否有价值。
6. 99元买断下愿为何种差异付款。

每条回答注明“现场观察／客户回忆／我们的推断”。不能量化时保留未知；未取得样本与明确回答也要记入拒绝和退出台账。

## 4. 可复用的演示脚本

创建两个虚构盘目录：同内容不同名、同名不同内容、一个读取失败文件。展示内容一致、仅哈希匹配、未知三种状态；拔掉一盘后只能查询有日期的历史记录。请用户找出哪些副本需重新接盘验证，观察是否误把未知当安全副本。

结束时让客户复述将收到什么、需要自己做什么、最担心哪一步。演示成功只证明理解，不作为付款或正式交付证据。

## 5. 典型异议与处理

- “免费软件也能查重复”：用同一组文件比较报告解释和离线索引。
- “为什么不能直接删”：当前交付仅只读核对。
- “照片不想上传”：展示处理边界，真实实现后还需核验网络行为。
- “10万文件要几分钟”：按硬件和总字节量实测后给范围，不凭数量承诺。

## 6. 从意向到试单的动作

| 节点 | 要完成的动作 | 留存证据 |
| --- | --- | --- |
| 资格确认 | 对齐近期任务、输入与决策人 | 原流程摘要、排除项 |
| 小样比较 | 同任务比较现有办法与拟议结果 | 差异及双方总耗时 |
| 完整报价 | 按实施方案给出金额、额度、交付和退出条件 | 范围版本、客户明确回应 |
| 启动确认 | 核实际可交付状态、输入齐备与约定付款节点 | 输入确认、真实交易凭据 |
| 交付验收 | 对照第三份文件，客户明确通过或退回 | 成果版本、验收意见 |
| 后续观察 | 按项目任务频率复用、续费或转介绍 | 使用记录与新付款分开 |

同一轮先保持原报价，记录拒绝原因；确需折扣时单独标为折扣样本，不当原价转化。客户缺输入则暂停排期。售前承诺只包含当前报价范围，不将未来愿景写进订单。付款、发票、退款和发布渠道在真实交易前按实际采用方式核验，此处不假定已具备条件。
