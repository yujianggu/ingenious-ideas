# 执行模板与交付标准

日期：2026-09-20。以下为空白工作模板，尚未发生招募、交易或交付。复制到以项目编号命名的实际实验文件后填写；不得把示例、假设写进“实际结果”栏。

## V3全生命周期入口

先使用[全生命周期项目方案模板](全生命周期项目方案模板.md)建立12阶段计划、R1—R5评审、六张管理台账以及上线／上市／结项记录。以下A—G继续用于访谈、报价和订单交付等具体执行；订单验收不替代项目发布验收，阶段G决策记录须注明对应R关口。

## A. 一页实验任务卡

| 字段 | 填写要求 |
| --- | --- |
| 项目／版本／负责人 | 固定编号；谁负责经营，谁负责专业审核 |
| 本轮问题 | 一句话，只验证一个主要风险 |
| 目标客户与排除对象 | 地区、行业、规模、近期任务；谁不接 |
| 使用者／付款人／验收人 | 分别登记，不能假定同一个人 |
| 现有替代与最近任务 | 客户当前怎么做，最近发生日期 |
| 输入与权限 | 必要资料、授权范围、脱敏方式、保留期限 |
| 本轮样本与观察周期 | 计划数和实际数分栏 |
| 继续门槛／停止门槛 | 在执行前填，事后改动记录理由 |
| 工时／现金上限 | 预算与实际分栏，含创始人时间 |
| 结论 | 未执行／证据不足／继续／调整／停止 |

## B. 访谈与替代对照

访谈先让客户描述最近一次真实任务：什么时候发生、怎么开始、交给谁、哪一步最慢、最后如何结束。再问替代工具为何没解决、什么情况下值得付钱和谁批准预算。不要先把产品功能念一遍诱导认同。

| 记录项 | 实际记录 |
| --- | --- |
| 日期、客户代号、角色、渠道许可 | 待填写 |
| 最近一次任务与可观察材料 | 待填写；没有材料说明原因 |
| 原流程各步骤与用时 | 待填写；估计与现场测量区分 |
| 原结果、返工、错误及后果 | 待填写；用户自述注明归属 |
| 替代工具和版本／测试日期 | 待填写 |
| 新旧流程同一任务的差异 | 待填写，计入客户学习和复核 |
| 看过完整报价后的反应 | 接受／拒绝／需批准；原话摘要 |
| 未解决问题与下一步 | 待填写 |

拒绝沟通、无购买预算、任务不合格分别计数，不删掉“不好看”的样本。对外联系和发布招募内容需实际执行授权；本模板本身未发送任何消息。

## C. 报价与范围确认单

客户：____；项目／版本：____；报价有效期：____；责任人：____。

| 项目 | 必填内容 |
| --- | --- |
| 购买结果 | 客户最终拿到什么，可如何使用 |
| 数量和额度 | 文件、岗位、题量、店铺、员工、容量或报告次数 |
| 客户输入 | 何时提供哪些资料，由谁确认最终版本 |
| 交付物 | 文件格式、产品版本、权限、指南、导出包 |
| 交付日期 | 从输入齐备和范围确认起算；延期处理方式 |
| 金额与支付节点 | 明确总金额、接入费与持续费，收费口径待选定渠道核实 |
| 验收标准 | 数值、状态、格式、可自主完成的任务 |
| 修订与缺陷 | 范围内修订次数；承诺内错误的修复义务独立列出 |
| 排除范围 | 写本项目具体不包含什么，不泛写“以实际为准” |
| 支持与退出 | 响应窗口、取消退款、数据导出、保留删除的约定 |
| 双方确认 | 确认人、日期、范围版本及可追溯记录 |

任何“以后想要”的功能先进入需求池，不自动成为本单范围。未形成明确条款前，不用模糊定金锁住客户。

## D. 输入检查与交付验收

输入检查：授权范围清楚；资料完整；版本唯一；责任人明确；缺项可列出；原件有备份或不覆盖。资料不齐暂停计时并告知缺项，不能假装已经开始完整交付。

| 检查项 | 证据／结果 | 负责人 | 未通过的处理 |
| --- | --- | --- | --- |
| 成果数量及格式与报价一致 | 待填 | 待填 | 补交或协商新时间 |
| 核心结果可复核 | 待填：对应测试或原件 | 待填 | 修正并重新验收 |
| 无未处理的严重错误 | 待填：问题单 | 待填 | 暂停交付受影响部分 |
| 客户可自主完成目标任务 | 待填：观察记录 | 待填 | 改进流程／补培训并计时 |
| 导出与退出路径可用 | 待填：导出文件／恢复结果 | 待填 | 修复后交付 |
| 客户验收意见已记录 | 待填：通过／退回及原因 | 待填 | 不以沉默替代确认 |

交付目录建议：01输入索引、02最终成果、03口径与说明、04验收、05变更与售后。真实敏感文件按项目受控存储，不默认放入公共研究仓库。

## E. 范围变更与售后问题单

| 字段 | 记录内容 |
| --- | --- |
| 原范围版本与问题编号 | 待填写 |
| 请求描述及提出人 | 待填写 |
| 分类 | 承诺内缺陷／输入错误／新增范围／使用求助 |
| 影响 | 数据、金额、状态、时间、客户可用性 |
| 处理与新增工时 | 待填写；缺陷不借变更收费逃避责任 |
| 费用与日期变化 | 仅新增范围需要重估，实施前明确 |
| 修复版本、复验、客户反馈 | 待填写 |

严重程度建议：A为数据泄露、原件破坏、关键结果错误；B为核心任务受阻但有可靠替代；C为一般体验问题。A先暂停相关流程并核查影响，B给临时路径和修复计划，C进入版本排期。响应不等于修复完成。

## F. 周报与漏斗台账

| 指标 | 计划 | 实际 | 证据或偏差原因 |
| --- | --- | --- | --- |
| 筛选／可联系／回复／合格客户数 | 待填 | 未执行 | 待填 |
| 演示／完整报价／实际付款数 | 待填 | 未执行 | 待填 |
| 完成任务／客户验收数 | 待填 | 未执行 | 待填 |
| 自主完成率 | 待填 | 未执行 | 明确分子分母 |
| 销售、研发、交付、支持小时 | 待填 | 未发生 | 分类别记录 |
| 到账、退款、渠道及工具支出 | 待填 | 未发生 | 对应凭据 |

付费转化率＝实际付款客户÷看过完整报价的合格客户；自主完成率＝无代操作完成目标任务数÷尝试该任务数。缺观察窗口记未知，不记0；真实观察到0才记0。

## G. 阶段决策记录

日期：____；项目：____；原假设：____；新增证据：____。

结果选择：继续当前范围／只调整一个假设／停止归档／证据不足。列出支持与反对证据，说明下一阶段预算及负责人与截止日期。若停止，保留失败原因、可复用资料与重新开启所需证据；不为了投入过时间而继续。

本模板适用于本批国内Top10；海外已有独立方案，C21及其他国内创意需另行确定范围，不自动扩大执行。
