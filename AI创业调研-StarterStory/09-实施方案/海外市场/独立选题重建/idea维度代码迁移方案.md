# 按 idea 维度拆分代码

用户纠正：coding 应隶属各 idea，不能集中在仓库最外层。此前的统一应用是助手误解，本次按项目边界纠正。

## 目标与约束

每个 `项目方案/OS-编号-名称/coding` 自带 backend、frontend、app，以及自己的 docs、scripts、deploy；按需包含项目内部 shared 与 tests。B04 使用现有项目目录，其余七项创建独立目录。每份 coding 可单独复制、安装、启动、打包，不运行时引用其他 idea 或仓库根的源码。

每项目只有自己的业务 API、界面入口、应用标识、浏览器会话键、数据目录与默认端口。B04 保留邀请/编辑/客户流程；其他项目使用本项目私有账户与记录。去掉统一产品选择器。

不恢复撤回的海外十项，不修改国内线程文件，不删除用户数据或依赖。已有混合数据库保留，并提供显式迁移工具和说明。原 V1 的 AI、支付和实物履约接入边界不变。

## 任务与验收

1. 冻结已验收源码，供此次迁移读取；临时副本不成为运行依赖。
2. 后端子任务：复制所属领域模块，隔离服务/账户/数据与路由，带入相关测试；其他产品 API 必须返回 404。
3. 网页子任务：各 idea 单项目登录与页面，只打包自身配置，分别设置代理端口、会话键；网页测试和构建通过。
4. 移动子任务：各 idea 单项目入口、独立应用标识和会话键；保留离线/同步功能；测试、类型检查、平台导出通过。
5. 根代理：恢复 B04 单项目代码，维护运行脚本、部署、文档与索引；安全搬移根 coding 的数据和依赖后移除根 coding。
6. 逐项目验证安装/构建边界、其他产品不可访问、文档路径、B04 回归；交叉审查并修复实际问题。
7. 提交纠正并更新此前推送分支，报告新的 idea 目录与验证结果。

项目路径与默认端口见代码迁移清单.json；清单仅用于迁移与导航，任何项目运行均不依赖它。
