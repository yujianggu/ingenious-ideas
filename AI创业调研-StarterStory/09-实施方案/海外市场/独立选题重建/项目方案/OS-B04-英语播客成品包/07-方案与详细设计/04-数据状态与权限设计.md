# OS-B04 数据、状态与权限设计

版本：1.1｜2026-09-20。已静态阅读实际app.js/logic.js；本文件描述现有整包版本模型，浏览器执行结果见[检查记录](../../../检查记录.md)。

## 1. 实际数据对象

| 对象 | 当前字段 | 约束 |
|---|---|---|
| Workspace | schema=1、product=OS-B04、episodes | 1–20期；浏览器key为os-b04-independent-v1；当前index/role/tab只在运行时，不导出 |
| Episode | id、title、brand、source、duration、notes、glossary、rights、phase、version、clips、chapters、history、events、manifest | duration为90–3600整数秒；clips恰好3个唯一ID；没有language/readyAt或同一期换源字段流程 |
| Clip | id、title、start、end、quote、context、post、checked、status、feedback | 无独立版本号；版本继承episode.version；当前状态draft/pending/approved/changes |
| Frozen review | version、sentAt、title、source、duration、chapters、clips、decisions | 送审内容快照保存；decisions随该版本客户决定更新。旧内容不覆盖，不等于不可篡改存证 |
| Event | time、version、action | 记录动作与时间，角色在动作/流程中体现，不是实名actorId或签字 |
| Manifest | type、episodeId、version、title、source、generatedAt、status、missingProductionAssets、clips、chapters | type=prototype-review-manifest；status=review-approved-media-not-rendered；必须与当前批准整包一致 |
| Session media | media、mediaUrl | 仅内存/object URL；选视频≤200MB；切episode/恢复/刷新后需重选，不写备份 |

## 2. 实际状态转换

Episode使用draft → editing → review → approved → manifest。

- 客户提交完整brief及rights=true，draft变editing；此后brief冻结，revision也不能重开它。
- 编辑Save excerpt校验非空文本和30–90秒整数范围；Save chapter notes检查非空。Send把三段置pending并保存整包版本快照，phase变review。
- 客户只能决定pending片段；Approve还需确认读过原话/上下文，Request changes需理由。三段全approved时episode变approved；存在changes时episode仍是review，以逐片状态显示退回，不能另写成独立episode状态。
- 编辑从review/approved/manifest发起revision：整包version+1、phase=editing、manifest=null、三段status=draft且checked=false。三段原有feedback暂留用于修订，保存该片段后当前feedback清空；旧版decisions保留原因。
- 修订后的三段必须全部重新回听、送审、批准。没有未修改段继承批准或独立片段版本。
- approved才可准备manifest；manifest仅列评审内容和缺失生产资产。再revision使清单失效。原型没有Delivered状态。

编辑阶段保存以提交的checked值为准，没有每次改字自动重置checked的内容哈希机制。因此“开启修订强制清三段回听”是已编码事实，“每次保存后都自动发现变化并要求回听”未实现；真实回听仍是编辑责任。

同一期源引用、时长、品牌约束的重开/换源完全未覆盖，不写成已实现的失效流程。生产若增加此能力，应重新确认授权、范围和交期，并使整包重新回听和审批。

## 3. 权限与工作区

| 动作 | 客户演示角色 | 编辑演示角色 |
|---|---|---|
| 提交brief/声明授权 | 仅draft可提交 | 不允许 |
| 保存片段/章节、送审 | 不允许 | 仅editing |
| 批准或有理由退回 | 仅review中的pending片段，版本须等于当前整包 | 不允许 |
| 开始新整包修订 | 不允许 | review/approved/manifest |
| 准备manifest | 不允许 | 仅approved |
| 查看历史/样例下载 | 可看；有manifest才可下载样例 | 同左 |
| 新建episode、备份/恢复 | 本地操作者可用 | 本地操作者可用 |

动作处理函数检查角色/状态；这只是单浏览器角色演示，不是身份认证、客户数据隔离或安全访问控制。生产需另建账号、工作室权限、邀请和可审核身份记录。

## 4. 备份校验与错误处理

导出/导入上限2MB；结构验证包含schema/product、1–20期、唯一ID、允许阶段、三片唯一ID、整数时码、版本和日期、历史快照与决定、当前冻结内容一致性、manifest与已批准内容一致性。draft/editing允许尚未送审的内容，不要求所有片段已回听；真正送审时再严检。

恢复先解析及验证，展示覆盖范围并确认；确认时再次校验且检查当前工作区是否在预览后变化。取消/解析错误/结构错误不覆盖。媒体不恢复。localStorage写失败显示备份提示；原型不能保证浏览器清理后数据仍在。

所有用户文本经转义展示；下载文件名使用固定clip编号/版本而非任意标题路径。备份并非加密，localStorage可由本地操作者修改，历史不可作为不可篡改法律证据。

## 5. 生产待建

无readyAt、暂停排期、实际验源、支付或正式交付状态。服务要求是素材齐备确认后7个自然日；正式运营须保存开工及变更确认，不能以brief提交时间替代。源替换、真实身份、授权证据、成品校验、交付回执和保存期限均待建/待执行。当前不提供episode删除流程。
