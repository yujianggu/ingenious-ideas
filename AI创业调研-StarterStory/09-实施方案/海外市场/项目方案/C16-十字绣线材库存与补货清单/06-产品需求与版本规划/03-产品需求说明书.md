# C16｜最终交付产品需求

海外产品设计V3｜2026-09-20｜以最终交付为目标的需求基线草案；交互原型用于评审，生产能力与实际业务验收未完成。

## 目标、买家和交付物

Thread Cabinet：首次录入后第二次备线仍能快速产生可信缺线清单。客户与验收角色：单国100种以上绣线且近期采购的个人；本人维护库存、付款及备线验收。

首版范围：手填／CSV库存、半束单位、单项目需求、缺线、入库撤销、导出恢复；不识色、不跨品牌转换、不默认云同步。容量：先5位真实绣者，每人20种高频色号；单品牌、一个活动项目。专业依赖：真实绣者／线材伙伴＋数量与语言审校。

本轮选择完整任务流程原型作为评审材料：可编辑输入、业务状态、修订、结果及导出连贯；正式后端、商业运营与专业审核留在实施阶段按需求交付。产品不向终端用户展示R1—R5、REQ编号或内部立项材料。

## 角色与入口

原型入口：My cabinet。角色切换仅在页脚“Prototype review tools”中供评审使用。外部客户入口不展示完整客户列表；正式产品必须根据真实登录或授权链接在服务端核验对象范围，不能依赖隐藏列表实现权限。

本地工具无需默认注册账号或上传文件。服务项目的工作人员入口是交付工作台，可由既有表单与内部工具承载，不把原型页面数量当成必须开发的新SaaS范围。

## 功能需求与正常／失败路径

### C16-OS-U01 库存录入

用户任务：保留品牌色号字符串与前导零，支持已知半束数量或待核。

状态变化：草稿 → 已保存。失败与边界：CSV必须预览、映射和报错；待核不能按零计算购物量。

验收：由相应业务角色用一组成功输入与一组失败输入完整走通；核对结果、版本、操作者、时间和恢复后的原数据，证据关联`C16-OS-UT01`。按钮反馈不单独构成通过。

### C16-OS-U02 项目缺线

用户任务：一个活动项目按需求减可用量计算缺线，多个色号形成清单。

状态变化：已保存 → 缺线清单。失败与边界：单位混用阻断；重复色号提示进入已有记录。

验收：由相应业务角色用一组成功输入与一组失败输入完整走通；核对结果、版本、操作者、时间和恢复后的原数据，证据关联`C16-OS-UT02`。按钮反馈不单独构成通过。

### C16-OS-U03 采购及耗用

用户任务：确认实际采购才入库，实际使用才扣减；记录可逆事件。

状态变化：缺线 → 已入库／已耗用。失败与边界：重复采购不翻倍；耗用不能负库存；撤销须针对未被后续修改的事件。

验收：由相应业务角色用一组成功输入与一组失败输入完整走通；核对结果、版本、操作者、时间和恢复后的原数据，证据关联`C16-OS-UT03`。按钮反馈不单独构成通过。

### C16-OS-U04 备份与恢复

用户任务：整个库存和事件导出，恢复前预览替换范围并确认。

状态变化：任意已保存状态 → 恢复后状态。失败与边界：损坏、类型错误、重复色号或不兼容版本不得覆盖当前库。

验收：由相应业务角色用一组成功输入与一组失败输入完整走通；核对结果、版本、操作者、时间和恢复后的原数据，证据关联`C16-OS-UT04`。按钮反馈不单独构成通过。

## 输入规格与样例

| 字段 | 用户名称 | 原型输入类型 | 虚构样例 |
| --- | --- | --- | --- |
| `title` | Colour code | text | 0310 |
| `stock` | Stock (skeins) | number | 1 |
| `need` | Project need (skeins) | number | 1.5 |

必需字段为空时不改变业务状态；提交后输入冻结，修订建立新版本。金额采用明确币种和最小货币单位；数量采用项目约定精度。色号、对象ID及编号保持字符串。日期须标明日期语义与业务时区。

## 交付、服务和质量要求

1. 正式版本同时提供约定成果、使用说明、支持入口、已知限制、导出退出方式和版本记录；上线前由接收人按09阶段签认。
2. 输入失败、处理中、已提交、审核通过、客户接收分别显示；失败保留有效旧数据，并提供重试或人工处理入口。
3. 服务的修订次数、交期、容量、额外需求报价与支持窗口以订单为准。订阅产品应能查看已购范围及取消方式；本地买断工具明确支持期和升级范围。
4. 数量与钱款不得静默舍入或混币；重复提交不生成重复结果。生产端按真实容量测试同账号、跨用户并发，关键写入具有一致性约束。
5. 键盘可完成主流程，焦点可见，错误与输入关联，状态变化可被辅助技术读到；窄屏避免横向溢出。
6. 真实资料、原文件、日志及备份的访问、保存、删除分别设计；恢复验证内容和权限，不仅检查文件是否存在。

## 国家与语言发布条件

当前可交互原型为en-US、USD和明确的UTC时间样例。德国、法国、荷兰分别要求de-DE、fr-FR、nl-NL术语审校、数字分隔符、货币、日期及实际业务时区验证；欧元样本不能替代三国独立验收。正式报价和税费展示、收款主体、退款及资料处理安排沿用公共方案并在发布前核实；没有在原型中声称已开通支付。

## 原型实现范围

多色号、半束数量、待核、缺线、采购耗用及撤销、JSON备份恢复可操作；未实现CSV导入、品牌目录和多项目占用。

浏览器本地记录可新增、切换、刷新保留、导出备份及预览恢复；这是评审辅助，不提供生产加密、账号隔离和持久保存保证。样本均为虚构；原型不接入真实外部服务。

## 完成定义

本文件4组用户任务与既有6组核心约束同时满足；正式成果格式可打开、复算／核对和完整恢复；目标语言用户自主完成任务；生产权限、恢复、收款和支持条件有实证。原型自动化通过只证明已实现的交互，不能将其余交付项标为完成。
