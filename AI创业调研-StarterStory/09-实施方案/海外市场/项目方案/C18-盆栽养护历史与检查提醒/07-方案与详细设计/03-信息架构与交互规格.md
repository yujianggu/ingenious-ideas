# C18｜信息架构与交互规格

海外产品设计V3｜2026-09-20｜以最终交付为目标的需求基线草案；交互原型用于评审，生产能力与实际业务验收未完成。

## 应用结构

[打开原型](原型/index.html)。品牌：Plant Journal；主承诺：Remember the last check. Plan the next one.。

工作区采用“对象列表 → Work任务页 → Deliveries成果页 → History活动页”。对象列表支持新增与切换；外部客户仅看被共享的当前任务。原型评审角色切换、浏览器备份和能力边界放在页脚，不混入客户任务按钮。

## 业务页面和状态

- **植物及位置**：保存植物、位置和用户记录，列表可切换不同植物。 状态：草稿 → 已保存；名称为空不保存；图片压缩、数量及备份容量在正式实现验收。
- **真实事件**：分别登记检查、浇水、施肥和换盆；每条显示时间、备注并可纠正。 状态：已保存 → 新事件；检查不自动算浇水；撤销保留痕迹，不用提醒完成伪造养护事实。
- **检查安排**：用户设置下次检查日期，应用显示到期列表和通知权限状态。 状态：已保存 → 已安排；通知失败仍可查任务；跨时区和夏令时规则明确；不保证植物健康。
- **完整恢复**：备份包含植物、事件、照片和计划；恢复先校验临时副本再切换。 状态：任意已保存状态 → 恢复后状态；缺图、损坏、不兼容拒绝覆盖；原型仅恢复文字和事件，不代表照片已支持。

## 交互规范

首次打开用虚构样例展示可完成任务。空结果给下一步指引；错误保留输入并说明原因；当前状态不适用的操作禁用。不可原位覆盖的版本在“Create new version”或“Edit source & resubmit”中显式重新建立。历史结果仍可查看。

下载成果使用真实浏览器下载；本地备份选择文件后先显示替换记录数，用户确认才覆盖，损坏文件保持原数据。原型实际可交付范围：多植物、四种事件、纠正、下次检查日期和JSON恢复可操作；无照片、系统通知、压缩或跨设备同步。

桌面采用左侧对象列表、右侧任务和结果；窄屏列表横向滚动、内容单列。语义标签、按钮、表单和状态区保留键盘访问。原型数据模型和前端不承担生产授权。

## 最终成果界面要求

正式成果须有版本、生成日期、对象范围、来源或附件索引、验收状态和可下载格式。对待审核／待确认／已交付的解释使用业务语言；专业审核和客户确认分开。下载失败列出缺项与恢复入口，不因页面能打开就视作交接完成。
