# C13｜信息架构与交互规格

海外产品设计V3｜2026-09-20｜以最终交付为目标的需求基线草案；交互原型用于评审，生产能力与实际业务验收未完成。

## 应用结构

[打开原型](原型/index.html)。品牌：Copy Check；主承诺：See which photo copies were actually checked.。

工作区采用“对象列表 → Work任务页 → Deliveries成果页 → History活动页”。对象列表支持新增与切换；外部客户仅看被共享的当前任务。原型评审角色切换、浏览器备份和能力边界放在页脚，不混入客户任务按钮。

## 业务页面和状态

- **选择及只读扫描**：用户明确选择两个目录／磁盘，确认只读核对；文件不上传。 状态：未扫描 → 扫描中；读取失败或断盘记录未知；不得以文件名相同判内容相同。
- **分级核对**：先尺寸过滤，再内容哈希，必要时逐字节复核；显示方法与读取时间。 状态：扫描中 → 完成／部分完成；哈希匹配与字节确认分开；取消后保留已完成项并标明不完整。
- **解释和重查**：用户看两侧路径、卷标、结果、失败原因，重连后显式重新核对。 状态：部分完成 → 新报告；旧报告不证明副本当前存在；重扫不能复用已变动文件的旧结论。
- **报告退出**：导出匹配、不同、未知项和检查范围；不提供自动删除。 状态：已扫描 → 导出；生产大文件流式处理、断点与符号链接策略另测，原型限用户选定小文件。

## 交互规范

首次打开用虚构样例展示可完成任务。空结果给下一步指引；错误保留输入并说明原因；当前状态不适用的操作禁用。不可原位覆盖的版本在“Create new version”或“Edit source & resubmit”中显式重新建立。历史结果仍可查看。

下载成果使用真实浏览器下载；本地备份选择文件后先显示替换记录数，用户确认才覆盖，损坏文件保持原数据。原型实际可交付范围：可读取用户主动选择的小文件并在浏览器计算SHA-256、逐字节比较和导出报告；内置样例单独标记。未遍历磁盘、未实现流式大文件或断盘恢复，不删除文件。

桌面采用左侧对象列表、右侧任务和结果；窄屏列表横向滚动、内容单列。语义标签、按钮、表单和状态区保留键盘访问。原型数据模型和前端不承担生产授权。

## 最终成果界面要求

正式成果须有版本、生成日期、对象范围、来源或附件索引、验收状态和可下载格式。对待审核／待确认／已交付的解释使用业务语言；专业审核和客户确认分开。下载失败列出缺项与恢复入口，不因页面能打开就视作交接完成。
