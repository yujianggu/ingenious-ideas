# B10｜最终交付产品需求

海外产品设计V3｜2026-09-20｜以最终交付为目标的需求基线草案；交互原型用于评审，生产能力与实际业务验收未完成。

## 目标、买家和交付物

Weekly Figures：按固定周期交付可复算报表与异常说明，减少客户整理和核对总时间。客户与验收角色：单国同平台2—5店铺运营团队；运营负责人使用、店主付款、指定数据负责人确认口径并验收。

首版范围：固定三表、单一报告币种、确定性计算、异常清单、来源追溯和口径字典；不做税务判断、多币种自动汇总或任意表格分析。容量：首期最多2家；一套订单／退款／广告输入、每月4次报告；接入与月包分开。专业依赖：当地电商数据业务负责人＋目标语言解释审校。

本轮选择完整任务流程原型作为评审材料：可编辑输入、业务状态、修订、结果及导出连贯；正式后端、商业运营与专业审核留在实施阶段按需求交付。产品不向终端用户展示R1—R5、REQ编号或内部立项材料。

## 角色与入口

原型入口：Client、Analyst。角色切换仅在页脚“Prototype review tools”中供评审使用。外部客户入口不展示完整客户列表；正式产品必须根据真实登录或授权链接在服务端核验对象范围，不能依赖隐藏列表实现权限。

本地工具无需默认注册账号或上传文件。服务项目的工作人员入口是交付工作台，可由既有表单与内部工具承载，不把原型页面数量当成必须开发的新SaaS范围。

## 功能需求与正常／失败路径

### B10-OS-U01 输入及口径

用户任务：客户按约定期间提供订单、退款、广告文件，确认币种、发生口径和冻结批次。

状态变化：草稿 → 已提交。失败与边界：缺字段、混币、列名变化和无法解释跨期必须阻断正式生成。

验收：由相应业务角色用一组成功输入与一组失败输入完整走通；核对结果、版本、操作者、时间和恢复后的原数据，证据关联`B10-OS-UT01`。按钮反馈不单独构成通过。

### B10-OS-U02 确定性计算与复核

用户任务：交付人员检查来源批次，按版本化规则对账，填写差异解释后出报告。

状态变化：已提交／修订 → 待验收。失败与边界：金额按最小货币单位计算；缺成本不输出净利润；差异未解释不交付。

验收：由相应业务角色用一组成功输入与一组失败输入完整走通；核对结果、版本、操作者、时间和恢复后的原数据，证据关联`B10-OS-UT02`。按钮反馈不单独构成通过。

### B10-OS-U03 验收及修订

用户任务：客户查看摘要与来源，确认本期成果或写明问题退回；修订保留旧报告。

状态变化：待验收 → 已验收／修订。失败与边界：重复交付或重复确认不增加结果；输入变更生成新交付版本。

验收：由相应业务角色用一组成功输入与一组失败输入完整走通；核对结果、版本、操作者、时间和恢复后的原数据，证据关联`B10-OS-UT03`。按钮反馈不单独构成通过。

### B10-OS-U04 最终工作簿

用户任务：交付摘要、店铺对照、异常、明细、口径字典、运行说明及版本索引。

状态变化：已交付 → 可下载。失败与边界：正式Excel必须与冻结输入复算一致；原型JSON只覆盖示例计算。

验收：由相应业务角色用一组成功输入与一组失败输入完整走通；核对结果、版本、操作者、时间和恢复后的原数据，证据关联`B10-OS-UT04`。按钮反馈不单独构成通过。

## 输入规格与样例

| 字段 | 用户名称 | 原型输入类型 | 虚构样例 |
| --- | --- | --- | --- |
| `title` | Reporting period | text | 2026-09-14 / 2026-09-20 |
| `sales` | Receipts (USD) | number | 12800 |
| `refund` | Refunds in period (USD) | number | 680 |
| `ads` | Advertising spend (USD) | number | 950 |
| `source` | Source batch reference | text | orders-week38 / refunds-week38 / ads-week38 |

必需字段为空时不改变业务状态；提交后输入冻结，修订建立新版本。金额采用明确币种和最小货币单位；数量采用项目约定精度。色号、对象ID及编号保持字符串。日期须标明日期语义与业务时区。

## 交付、服务和质量要求

1. 正式版本同时提供约定成果、使用说明、支持入口、已知限制、导出退出方式和版本记录；上线前由接收人按09阶段签认。
2. 输入失败、处理中、已提交、审核通过、客户接收分别显示；失败保留有效旧数据，并提供重试或人工处理入口。
3. 服务的修订次数、交期、容量、额外需求报价与支持窗口以订单为准。订阅产品应能查看已购范围及取消方式；本地买断工具明确支持期和升级范围。
4. 数量与钱款不得静默舍入或混币；重复提交不生成重复结果。生产端按真实容量测试同账号、跨用户并发，关键写入具有一致性约束。
5. 键盘可完成主流程，焦点可见，错误与输入关联，状态变化可被辅助技术读到；窄屏避免横向溢出。
6. 真实资料、原文件、日志及备份的访问、保存、删除分别设计；恢复验证内容和权限，不仅检查文件是否存在。

## 国家与语言发布条件

当前可交互原型为en-US、USD和明确的UTC时间样例。德国、法国、荷兰分别要求de-DE、fr-FR、nl-NL术语审校、数字分隔符、货币、日期及实际业务时区验证；欧元样本不能替代三国独立验收。正式报价和税费展示、收款主体、退款及资料处理安排沿用公共方案并在发布前核实；没有在原型中声称已开通支付。

## 原型实现范围

手填发生额、按美分计算、版本交付和JSON导出可操作；未实现源文件映射、自动对账、逐笔追溯或六表Excel工作簿。

浏览器本地记录可新增、切换、刷新保留、导出备份及预览恢复；这是评审辅助，不提供生产加密、账号隔离和持久保存保证。样本均为虚构；原型不接入真实外部服务。

## 完成定义

本文件4组用户任务与既有6组核心约束同时满足；正式成果格式可打开、复算／核对和完整恢复；目标语言用户自主完成任务；生产权限、恢复、收款和支持条件有实证。原型自动化通过只证明已实现的交互，不能将其余交付项标为完成。
