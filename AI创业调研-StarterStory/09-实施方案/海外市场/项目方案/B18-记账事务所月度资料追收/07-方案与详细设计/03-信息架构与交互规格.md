# B18｜信息架构与交互规格

海外产品设计V3｜2026-09-20｜以最终交付为目标的需求基线草案；交互原型用于评审，生产能力与实际业务验收未完成。

## 应用结构

[打开原型](原型/index.html)。品牌：Month Folder；主承诺：Know what is still missing this month.。

工作区采用“对象列表 → Work任务页 → Deliveries成果页 → History活动页”。对象列表支持新增与切换；外部客户仅看被共享的当前任务。原型评审角色切换、浏览器备份和能力边界放在页脚，不混入客户任务按钮。

## 业务页面和状态

- **期间清单**：记账员创建客户／期间，专业人确认必需项和不适用处理规则。 状态：草稿 → 已开放；清单模板不可跨国直接套用；机构、客户和期间隔离。
- **客户提交**：客户按指定项目提交文件并查看待审／退回原因。 状态：缺项／退回 → 待审；上传成功不等于审核通过；期间错误、上传中断和撤销链接分别处理。
- **人工审核**：记账员通过、填写原因退回或有据标不适用。 状态：待审 → 通过／退回／不适用；所有必需项通过或有依据不适用才齐套；不能靠上传数量判断。
- **齐套和导出**：客户可查看仍需处理的项目；记账员导出期间包及审核状态。 状态：审核完成 → 齐套；提醒去重、暂停及误发处理需正式联调；原型不发送催办。

## 交互规范

首次打开用虚构样例展示可完成任务。空结果给下一步指引；错误保留输入并说明原因；当前状态不适用的操作禁用。不可原位覆盖的版本在“Create new version”或“Edit source & resubmit”中显式重新建立。历史结果仍可查看。

下载成果使用真实浏览器下载；本地备份选择文件后先显示替换记录数，用户确认才覆盖，损坏文件保持原数据。原型实际可交付范围：两项期间清单、文件名登记、人工通过／退回／不适用和齐套判断可操作；不保存附件正文，不发送催办，无真实权限隔离。

桌面采用左侧对象列表、右侧任务和结果；窄屏列表横向滚动、内容单列。语义标签、按钮、表单和状态区保留键盘访问。原型数据模型和前端不承担生产授权。

## 最终成果界面要求

正式成果须有版本、生成日期、对象范围、来源或附件索引、验收状态和可下载格式。对待审核／待确认／已交付的解释使用业务语言；专业审核和客户确认分开。下载失败列出缺项与恢复入口，不因页面能打开就视作交接完成。
