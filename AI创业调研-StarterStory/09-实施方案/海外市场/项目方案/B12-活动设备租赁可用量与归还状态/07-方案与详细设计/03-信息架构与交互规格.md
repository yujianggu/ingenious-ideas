# B12｜信息架构与交互规格

海外产品设计V3｜2026-09-20｜以最终交付为目标的需求基线草案；交互原型用于评审，生产能力与实际业务验收未完成。

## 应用结构

[打开原型](原型/index.html)。品牌：Rental Board；主承诺：Returned is not the same as ready.。

工作区采用“对象列表 → Work任务页 → Deliveries成果页 → History活动页”。对象列表支持新增与切换；外部客户仅看被共享的当前任务。原型评审角色切换、浏览器备份和能力边界放在页脚，不混入客户任务按钮。

## 业务页面和状态

- **订单占用**：仓管按器材编号与时间建立占用，校验同器材已有有效订单。 状态：草稿 → 已预约；同器材时间交叉拒绝；起止时间反向拒绝；正式环境服务端并发锁定。
- **出库归还**：出库核就绪和订单，逐件登记归还；归还进入待检。 状态：已预约 → 已出库 → 待检；部分归还按件记录，延期重新检查冲突；不可自动全部恢复可租。
- **检查及维修**：仓管检查后恢复就绪；损坏转维修，修好后必须复检。 状态：待检 → 就绪／维修 → 待检；未就绪不得再次出库；弱网提交失败显示未提交，不重复记事件。
- **交接与盘点**：按器材查状态、占用与流转历史；导出账实差异和交接清单。 状态：任意状态 → 原状态；首期50件基线需客户签认，原型单件订单不代表已实现批量扫码。

## 交互规范

首次打开用虚构样例展示可完成任务。空结果给下一步指引；错误保留输入并说明原因；当前状态不适用的操作禁用。不可原位覆盖的版本在“Create new version”或“Edit source & resubmit”中显式重新建立。历史结果仍可查看。

下载成果使用真实浏览器下载；本地备份选择文件后先显示替换记录数，用户确认才覆盖，损坏文件保持原数据。原型实际可交付范围：单序列号订单、时间冲突、出库、归还、检查与维修可操作；未实现多件数量、扫码、延期重排和跨终端并发。

桌面采用左侧对象列表、右侧任务和结果；窄屏列表横向滚动、内容单列。语义标签、按钮、表单和状态区保留键盘访问。原型数据模型和前端不承担生产授权。

## 最终成果界面要求

正式成果须有版本、生成日期、对象范围、来源或附件索引、验收状态和可下载格式。对待审核／待确认／已交付的解释使用业务语言；专业审核和客户确认分开。下载失败列出缺项与恢复入口，不因页面能打开就视作交接完成。
